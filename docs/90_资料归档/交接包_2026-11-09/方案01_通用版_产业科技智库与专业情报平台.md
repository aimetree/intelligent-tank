# I｜A业务的战略定位与产品边界

## 1. 业务定义与服务范围

产业科技智库与专业情报业务面向技术密集型产业，把科研、技术、产品、竞争、政策、市场、工程应用和产业资源转化为可持续更新的专业数据、研究成果与决策依据。其研究对象既包括外部产业世界，也包括经合法授权的客户内部研究资料；主要交付是“可信知识和研究判断”，而非直接替代客户的工程开发或生产控制。

| 技术理解 | 产业理解 |
|---|---|
| 材料、工艺、算法、科研团队、专利、技术成熟度与证据 | 企业、产品、市场、客户、项目、政策、标准和竞争格局 |

| 专业比较 | 持续判断 |
|---|---|
| 对技术性能、工程条件、成本及应用要求开展可比性审查 | 以追踪、专题研究和专业知识工作流支持长期决策 |

## 2. A业务为什么适合自主建设

与依赖现场设备或客户工业运行数据的业务不同，A可以使用公开及合法授权的数据主动构建基础产品。即使尚未签订客户合同，也能够积累研究方法、行业本体、科技情报、产品档案、指标库和Agent工作流。不过，“开发时不依赖客户”不等于“商业化不需要验证”：信息是否足够有用、专业深度是否超过客户内部研究、愿不愿持续使用，都需要真实客户检验。

| **条件** | **A业务的特点** | **实际设计含义** |
|---|---|---|
| 开发启动 | 可以先使用公开、授权数据及专业研究经验 | 优先沉淀可复用数据、工具和研究方法 |
| 专业深度 | 不同产业有很强的专有术语和评价方法 | 行业包保留专业规则，不强求通用模型覆盖全部领域 |
| 持续维护 | 信息更新、数据核查和专业审核是长期成本 | 监测范围和数据授权必须受控 |
| 客户差异 | 制造商、咨询公司、政府、科研机构需要不同成果 | 同一知识底座，形成不同产品与权限 |
| 规模化挑战 | 容易退化为按客户反复写报告的服务 | 将研究主题、对象、证据与方法结构化，控制定制范围 |

## 3. 业务范围与边界

| **范围内：A的主要职责** | **不自动包含：需要单独界定** |
|---|---|
| 产业、科研、技术及竞品信息追踪 | 客户设备模型开发与工程设计实施 |
| 产品性能及技术路线专业比较 | 现场数据采集系统与生产设备集成 |
| 政策、标准、产业统计及市场项目研究 | 实际生产流程控制及闭环优化 |
| 技术经济性研究、竞争分析与研究报告 | 受法律监管的正式专利或合规法律意见 |
| 专业数据整理、知识平台、研究Agent和API | 未经授权重分发第三方数据库或客户私有资料 |

## 4. 面向的核心问题

> **▪** 技术发生了什么变化？哪些证据可靠，哪些结果仍停留在研究阶段？
>
> **▪** 谁在研发和销售相关技术？其产品与竞争路线有什么差别？
>
> **▪** 某项性能、成本或市场数据能否在相同口径下比较？
>
> **▪** 哪些政策、标准、市场需求及工程项目会影响技术选择？
>
> **▪** 应继续监测什么、深入研究什么、暂缓判断什么？

# II｜八大可迁移的专业研究模块

模块是研究能力的集合，不对应固定数量的订阅产品或独立软件。每个模块均采用统一的输入来源、专业对象、比较规则、分析方法和输出结构，并通过研究主题相互调用。

## M01｜科研前沿与技术创新

识别技术方向、科研团队、论文成果和研发进展，区分创新性、实验真实性与应用成熟度。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 论文、预印本、科研团队、资助项目、技术路线、实验方法与技术转化 |
| 核心方法 | 术语体系、研究主题追踪、引用/合作关系、实验条件抽取、证据分级 |
| 标准问题 | 有什么新技术？解决了什么问题？验证条件和局限是什么？是否有可重复性？ |
| 标准成果 | Research Radar、Technology Roadmap、Research Group Atlas、技术成熟度档案 |
| 迁移配置 | 替换行业科研关键词、关键性能指标、重要期刊和研究团队池 |

> **跨行业例子**
>
> 某膜技术企业示例：CO₂/CH₄分离膜材料、新型复合膜及工程化研究；电池示例：界面传感、电池安全诊断、材料退化研究。

## M02｜企业、竞争格局与产品情报

识别竞争主体、产品层级、商业化状态、服务能力和技术策略，关注实际可替代产品。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 企业、品牌、产品系列、技术规格、商业应用、合作和竞争事件 |
| 核心方法 | 竞争者分层、产品字段标准化、产品对照、变化监测、可靠性标注 |
| 标准问题 | 谁在竞争？同类产品能否比较？竞争范围是材料、组件还是完整方案？ |
| 标准成果 | Competitor Atlas、Product Benchmark、Competitive Landscape、竞品动态 |
| 迁移配置 | 替换产品分类、性能指标、客户购买对象与竞争地域 |

> **跨行业例子**
>
> 某膜技术企业示例：Evonik、Air Liquide、UBE、MTR等的膜组件与系统服务；电池示例：内部诊断传感器、BMS或电芯监测产品。

## M03｜技术路线、工程与应用情报

把研究成果、产品技术与具体工况、工业系统和应用要求联系起来，但不代替工程实施。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 技术流程、工程设计、设备、系统指标、公开工业案例及替代技术 |
| 核心方法 | 技术路线地图、工艺条件对比、系统边界定义、行业专家审核 |
| 标准问题 | 某技术在哪种规模和条件下适用？材料性能能否传导到系统收益？ |
| 标准成果 | Technology Route Atlas、Industrial Casebook、Application Fit Review |
| 迁移配置 | 替换设备/工艺分类、工程指标、性能约束、替代技术集合 |

> **跨行业例子**
>
> 某膜技术企业示例：膜分离与PSA/吸收等路线在特定气体工况的比较；LCA示例：生产过程路线与系统边界。

## M04｜数字技术、软件与AI创新情报

研究数字孪生、建模、AI、自动化与专业软件的技术发展及可验证应用。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 科研模型、数字孪生、工业软件、算法、AI Agents、实际应用和软件生态 |
| 核心方法 | 科研对标、模型验证标准、开源/商业能力比较、部署与数据前提分析 |
| 标准问题 | 新方法解决了什么？真实数据验证到了何种程度？商业软件是否已有类似能力？ |
| 标准成果 | Digital Technology Watch、AI & Software Landscape、Modelling Benchmark |
| 迁移配置 | 替换行业模型、常用软件、数据类型、评价和验证要求 |

> **跨行业例子**
>
> 某膜技术企业示例：膜分离数字孪生与混合建模情报；能源示例：电池状态诊断模型及AI智能研究工具。

## M05｜政策、标准与产业环境

跟踪政策法规、标准及产业支持变化，解释对特定技术和市场的适用范围。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 法律法规、政策文件、标准、市场准入、技术规范、产业支持政策 |
| 核心方法 | 地域与生效状态管理、标准版本追踪、条款-产品-场景映射 |
| 标准问题 | 哪些要求具法律约束？适用于哪个产品/地区？与市场机会有何联系？ |
| 标准成果 | Policy & Standards Atlas、Regulatory Watch、Impact Analysis |
| 迁移配置 | 替换监管地区、产品类别、标准层级、行业分类与周期 |

> **跨行业例子**
>
> 某膜技术企业示例：工业气体、生物天然气、膜材料与工程设备要求；LCA示例：碳核算、产品环境足迹相关标准。

## M06｜市场、客户、应用与产业项目

结合技术适用性识别真实产业需求、下游客户和项目，而非仅报告宏观规模。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 市场细分、行业需求、下游客户、设备商、系统商、招采与公开项目 |
| 核心方法 | 应用—指标映射、客户角色区分、项目证据与状态跟踪、区域分类 |
| 标准问题 | 谁采购？需求来自哪里？项目是否真实？哪些指标会决定技术选择？ |
| 标准成果 | Market & Application Atlas、Project Intelligence、Customer Ecosystem Map |
| 迁移配置 | 替换应用市场、购买角色、项目来源、政策与性能标准 |

> **跨行业例子**
>
> 某膜技术企业示例：沼气提纯、工业CO₂及相关系统集成商；电池示例：电芯厂、储能运营商与BMS开发商。

## M07｜专利、供应链与合作生态

研究技术布局、关键供应链、科研合作及授权关系，识别创新网络。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 公开专利、申请人、专利族、关键材料、供应商、科研机构和合作网络 |
| 核心方法 | 专利族归并、技术分类、供应链环节、来源验证与权益状态管理 |
| 标准问题 | 谁拥有相关技术布局？关键资源在哪里？哪些合作主体值得关注？ |
| 标准成果 | IP Landscape、Supply Chain Atlas、Innovation Network |
| 迁移配置 | 替换专利分类、材料与设备链条、重点地域及技术许可框架 |

> **跨行业例子**
>
> 某膜技术企业示例：膜材料、组件制造与分离工艺专利；LCA示例：行业数据、认证机构和相关供应链组织。

## M08｜综合对标、技术经济性与战略研究

从其他模块调用证据和方法，对具体技术、市场或竞争问题形成结构化判断。

| **研究维度** | **内容** |
|---|---|
| 研究对象 | 技术路线、产品、成本、系统效果、政策影响、市场与合作机会 |
| 核心方法 | 多指标对标、口径归一、情景和敏感性分析、证据矩阵、专家复核 |
| 标准问题 | 哪种选择适用于什么条件？哪些信息缺失？结论在何种假设下成立？ |
| 标准成果 | Benchmark Studio、Techno-economic Review、Strategic Insight |
| 迁移配置 | 替换行业经济指标、成本边界、关键假设和专业判断规则 |

> **跨行业例子**
>
> 某膜技术企业示例：特定分离工况下膜与其他技术的适用性和经济性；LCA示例：不同牧场/过程方案的环境影响评价。

# III｜模块与产品的关系：四层产品架构

## 1. 四层结构与关系

| **层级** | **组成** | **它是什么** | **不是什么** |
|---|---|---|---|
| L1 共享研究与数据底座 | 采集、知识、数据治理、Agent、研究和评价规则 | 支撑所有行业的复用能力 | 不是每客户单独重建的一套系统 |
| L2 标准产品 | Radar、Atlas、Research Studio、Workspace、API | 具有明确用户和功能的产品 | 不是八个模块对应八款软件 |
| L3 行业知识包 Industry Pack | 行业术语、实体、指标、来源、技术路线、研究模板 | 可加载的专业领域知识和方法 | 不是一个专属客户数据库 |
| L4 客户工作空间 | 关注清单、授权文档、专属研究、权限与历史判断 | 针对客户目标的应用与服务边界 | 不能未经许可反哺到其他客户 |

> **组合逻辑**
>
> 产品能力可复用；行业包补充专业语义与评价方法；客户空间配置关注对象和授权数据。客户不需要采购全部产品，行业知识包也可以单独形成专业数据或研究服务。

## 2. 标准产品组合（SKU设计）

| **标准产品** | **核心内容** | **交付/收费形式** | **主要用户** |
|---|---|---|---|
| P01 Intelligence Radar | 监测企业、科研、政策、技术与市场变化；支持主题订阅、事件去重、变化推送和证据核查。 | 订阅/年度服务 | 所有客户类型 |
| P02 Technology & Product Atlas | 企业、产品、技术、研究团队、标准、专利和项目结构化检索及跨对象关联。 | 软件/数据授权 | 制造商、咨询、科研 |
| P03 Evidence & Benchmark Studio | 性能与技术指标比较、可比性审核、技术路线和技术经济性分析、可复现研究表。 | 研究工具/专业分析 | 技术企业、咨询、研究机构 |
| P04 Policy & Market Intelligence | 政策标准、市场及招采项目、重点地区与下游应用追踪。 | 专题/数据订阅 | 企业、政府、咨询 |
| P05 Research & Reporting Studio | 专题研究工作流、研究模板、证据引用、图表和报告生成及人工审核。 | 软件/专项研究 | 咨询、政府、企业 |
| P06 Intelligence Workspace | 客户主题空间、授权知识、协作研究、专业Agent和持续研究历史。 | 企业授权/订阅 | 企业、研究团队 |
| P07 Professional Data & API | 领域数据包、指标与研究对象接口、合规数据馈送和嵌入式组件。 | 数据/API许可 | 咨询、软件及系统伙伴 |

## 3. 模块—产品映射矩阵

| **研究模块** | **主要依托产品** | **典型输出** |
|---|---|---|
| M01 科研技术 | Radar / Atlas / Research Studio | 科研雷达、研究团队、技术路线 |
| M02 竞争产品 | Radar / Atlas / Benchmark | 竞品数据、性能对照、竞争格局 |
| M03 工程应用 | Atlas / Benchmark / Research Studio | 工艺与应用案例、系统技术比较 |
| M04 数字技术 | Radar / Atlas / Benchmark | 数字孪生、模型与软件对标 |
| M05 政策标准 | Radar / Policy & Market | 政策库、标准条款关联、变化提醒 |
| M06 市场项目 | Atlas / Policy & Market / API | 产业链、应用、客户与项目 |
| M07 专利生态 | Atlas / Data & API | 专利布局与供应链生态 |
| M08 综合战略 | Benchmark / Research Studio / Workspace | 经济性、竞争及决策研究 |

## 4. 产品不必一次绑定全部功能

企业可先从竞品图谱或科技雷达使用，咨询机构可只采购专业数据及报告工具，政府相关机构可采购政策与产业映射专题，科研机构可只使用科技雷达和研究数据库。共享底座需要支持不同产品组合和访问权限，而不是把所有能力包装成单价昂贵的“超级平台”。

# IV｜专业数据、知识图谱与研究质量体系

## 1. 数据来源分级与获取策略

| **来源** | **可利用的内容** | **核查重点** |
|---|---|---|
| 官方公开来源 | 政策、标准目录、公司公告、公开产品规格、招采与工程项目 | 真实性、发布日期、版本与适用范围 |
| 学术开放元数据 | 论文、DOI、作者、机构、资助与引用关联 | 学术身份匹配、撤稿/修订、原文版权 |
| 专利信息来源 | 公开专利、法律状态及技术分类 | 专利族归并、使用许可与法律状态 |
| 商业数据平台 | 企业工商、行业研究、专业技术和市场数据 | 数据许可、费用、API调用与再分发边界 |
| 客户授权资料 | 内部报告、研发资料、项目档案和关注清单 | 客户隔离、用途、保密与权属 |
| 专业人工研究 | 模型计算、技术比较、人工调查与访谈 | 方法、假设、样本、审核与可复现性 |

可验证的数据接入参考包括OpenAlex（论文、作者、机构和研究主题元数据）、Crossref（DOI、书目及修订元数据）、EPO Open Patent Services、WIPO PATENTSCOPE以及合适的企业数据API。具体使用范围和条款应分别核查，尤其不能因为“能够查询”就认为具有商业转售原始数据的许可。

## 2. 最小通用对象模型

| **对象** | **通用字段** | **行业差异字段** |
|---|---|---|
| Organisation 企业/机构 | 唯一ID、别名、地区、类型、来源、有效期 | 行业角色、能力层级、产品或监管身份 |
| Technology 技术 | 定义、分类、研究状态、关联证据 | 技术路线、工程约束、成熟度指标 |
| Product 产品 | 名称、版本、制造商、用途、状态 | 材料组成、组件参数、设备规格 |
| ResearchOutput 研究成果 | 标题、DOI/链接、时间、机构、来源 | 具体实验条件、应用与模型误差 |
| Metric 指标 | 名称、单位、统计口径、测试边界 | 渗透率、CE、LCA排放因子等 |
| Policy/Standard 政策标准 | 地区、机构、日期、版本与有效状态 | 适用对象、强制性、具体条款 |
| Project 应用项目 | 对象、地点、状态、时间、主办方 | 工业条件、应用规模及技术路线 |
| Evidence 证据 | 原文、片段、来源、核查和许可 | 学科相关的可靠性与实验信息 |
| Assessment 研究判断 | 问题、结论、证据、假设、审核人 | 行业评价逻辑与阈值 |

## 3. 知识图谱的关系类型

| **主语** | **关系** | **宾语** | **用途** |
|---|---|---|---|
| 企业 | 研发 / 制造 / 供应 | 技术 / 产品 | 技术竞争和产品图谱 |
| 研究团队 | 发表 / 开发 | 论文 / 技术 | 科研前沿与成果追踪 |
| 专利 | 主张 / 涉及 | 技术 / 材料 | 研发和知识产权地图 |
| 产品 | 满足 / 受限于 | 标准 / 指标 | 市场准入与性能分析 |
| 应用场景 | 要求 | 性能指标 / 工况 | 技术适用性与竞品比较 |
| 工程项目 | 采用 / 采购 | 技术 / 企业 | 商业应用与产业生态 |
| 研究结论 | 依据 / 适用于 | 证据 / 条件 | 审计、复核与更新 |

## 4. 证据可信度与不确定性

| **证据类别** | **释义** | **推荐呈现** |
|---|---|---|
| E1 已核实事实 | 有可核实的一手来源，且条件明确 | 来源及时间可追溯 |
| E2 第三方或企业公开声明 | 来源明确但未经独立验证 | 标明“公开声明”及适用边界 |
| E3 学术/实验数据 | 在特定测试和样本条件成立 | 记录工况、样本和验证方法 |
| E4 模型与情景结果 | 依据输入假设和模型推演 | 展示假设、范围及敏感性 |
| E5 专业判断与待验证推断 | 对多项证据解释后形成 | 写明依据、分歧和下一步验证 |

对高技术密度行业尤其要区分材料性能与系统性能、实验结果与工业验证、单个案例与总体市场、当前法规与草案、申请专利与有效授权专利。AI辅助生产的文本不作为独立证据。

## 5. 数据权限、许可与客户隔离

> **▪** 公共或获得商业再利用许可的数据可用于合规的通用行业包；受限数据库按订阅和授权范围使用。
>
> **▪** 客户保密资料进入独立授权工作空间，与通用知识库物理或逻辑隔离；不得自动跨客户检索或训练。
>
> **▪** 通用研究方法、公开来源的标准化字段和行业本体可按权利归属复用，但客户专属报告及委托成果按合同执行。
>
> **▪** 资料输出需要区分“可展示链接/摘要”“可下载原始数据”“允许转授权API”等不同许可层次。
>
> **▪** 定期审查版权、数据库权利、个人数据、跨境传输、科研合作和资料更新的合规需求。

## 6. AI Agent的合理角色

| **Agent/工作流** | **主要任务** | **必须保留的人类控制** |
|---|---|---|
| Research Monitor | 技术论文、企业动态、政策项目监测与去重 | 主题适配和重要性筛选 |
| Entity Resolver | 识别企业、技术、科研团队、产品版本 | 关键实体身份合并审核 |
| Evidence Extractor | 从合规来源提取指标、条件、引文 | 关键参数及单位二次核对 |
| Benchmark Assistant | 准备性能矩阵、缺失字段及口径检查 | 可比性和技术结论审核 |
| Research Composer | 生成研究大纲、图表和证据链 | 专业表达、结论和引用审核 |
| Policy Watch | 政策条款变化、地区和状态识别 | 法规效力及适用性专业复核 |

## 1. 客户类别与价值主张

| **客户** | **最关注的问题** | **核心产品组合** | **使用特点** |
|---|---|---|---|
| 工业技术企业与制造商 | 竞品、技术路线、研发团队、标准及新市场 | P01+P02+P03+P06 | 持续监测+专项研究 |

## 2. 服务形态：持续与专项的边界

| **服务形态** | **客户获得** | **能否标准化** | **界定边界** |
|---|---|---|---|
| 主题订阅 | 持续情报、重要变化、可查询历史 | 高 | 明确行业包、关注主题和覆盖范围 |
| 数据与专业数据库 | 领域对象、产品指标、来源与更新 | 高—中 | 明确授权、字段、更新与使用权 |
| 研究工作空间 | 知识管理、研究Agent、证据与模板 | 中—高 | 账户、权限、数据隔离与服务级别 |
| 专题研究 | 技术路线、竞争、市场或经济性报告 | 中 | 限定研究问题、范围和数据条件 |
| 定制知识包 | 特定行业字段和研究规则 | 中 | 明确通用与专属开发边界 |
| API/OEM数据组件 | 嵌入式知识和研究接口 | 中—高 | 技术及数据许可、用量与责任 |

## 3. 报告不应成为唯一产品

标准报告、专题咨询和深度研究可以产生价值，但所有可复用的企业、产品、指标、方法与证据应在许可范围内进入结构化资产。研究报告只是这些资产在某一问题上的呈现方式。若每单都从搜索开始、每次都重写方法，则很难形成可规模化的专业情报产品。

# VI｜国内外竞争格局与业务差异化

## 1. 竞争者需要按能力类型划分

| **竞争类别** | **代表企业/平台** | **其公开可见能力** | **业务A需要重点思考的竞争** |
|---|---|---|---|
| 综合市场情报 | AlphaSense、GlobalData | 多源资料、AI研究、行业数据、监测、报告与团队工作流 | 广泛信息覆盖与成熟研究平台 |
| 研发/专利技术情报 | Patsnap/智慧芽 | 科研专利数据、技术检索、专业Agent及API | 深度技术情报已有成熟产品 |
| 垂直行业数据 | Wood Mackenzie、部分行业专业数据商 | 能源/自然资源资产、项目、价格、市场和预测 | 纵向专业数据与长期行业方法 |
| 技术和创新公司数据库 | CB Insights | 创新公司、市场、投资与竞争情报 | 技术企业和投资交易信息 |
| 中国行业研究与智库 | 头豹、赛迪顾问等 | 行业研究、政策咨询、智能行研和专业报告 | 本土行业研究与政府市场 |
| 企业原始数据服务 | 企查查等 | 企业工商、知识产权、经营与API | 可作为上游数据供应，也有部分替代功能 |
| 客户内部与通用AI | 内部研究员、搜索引擎及通用LLM | 低门槛整理、检索和初步研究 | “自动搜索+生成报告”本身缺乏壁垒 |

## 2. 竞争分析应比较具体功能，而不是只比较品牌

| **功能与竞争变量** | **业务A需达到的标准** | **判断方式** |
|---|---|---|
| 内容来源 | 合法、可追溯、多源且持续更新 | 原始数据及商业许可审查 |
| 专业语义 | 理解具体技术、产品和工况 | 行业指标与对象链接完整度 |
| 研究自动化 | 减少重复工作，不牺牲可信度 | 人工审核工时和错误率 |
| 技术比较 | 保证层级及工况一致，说明不确定性 | 真实技术对比案例与专家复核 |
| 研究工作流 | 从问题到证据、分析、成果可追溯 | 研究全过程记录与复现 |
| 行业深度 | 能够回答通用工具不易处理的专业问题 | 真实客户案例、研究准确性 |
| 客户适配 | 不同客户类型通过配置而非重建使用 | 跨客户部署工作量 |
| 经济性 | 数据和审核成本可控，长期维护有资源 | 单位活跃用户、行业包与研究主题成本 |

## 3. 竞争格局的可行位置

> **不应宣称的差异化**
>
> AI自动生成行业报告、知识图谱、专利检索、研发Agent、物理模型与专业数据结合，市场上都有不同形式的成熟供给。不能把这些通用概念表述为没有竞争者的独特技术。

可验证的定位是假设：针对高技术密度、常规综合数据平台覆盖不深的工业细分领域，将“有来源的专业知识+可比较的科技/产品指标+实际工程约束+行业研究工作流”整合为轻量可迁移产品。是否有竞争优势，需要通过具体客户与替代方案的实际对比证明。

## 4. 与竞品既竞争，也可采购和集成

OpenAlex、Crossref和专利数据服务可作为数据来源；企查查可作为经授权的企业信息供应；Patsnap或其他专业专利平台可能成为高复杂度专利任务的工具；成熟大模型可用于受控研究工作流。业务A无需将一切外部平台都视为需要自研替代的竞争者。

# VII｜跨行业迁移：通用架构与行业知识包

## 1. 迁移的核心是“可配置结构”而非“复制结论”

可迁移部分包括信息源接入框架、实体识别、更新监测、研究审核、证据和权限、图谱关系以及报告模板；不可直接搬迁的包括专业术语、科学机制、技术评价阈值、工程工况、政策适用范围和客户专有资料。新行业进入成本主要由专业知识建设和数据质量决定，而非仅由软件代码决定。

| **迁移层** | **可以复用的部分** | **需要重建或适配** |
|---|---|---|
| 数据基础 | API适配器、采集/去重、版本与来源体系 | 具体数据渠道、专业术语和许可范围 |
| 知识语义 | 企业、产品、论文、专利等通用对象 | 技术子类、产品体系、关系规则 |
| 技术评价 | 单位校验、可比性、情景分析工具 | 行业科学指标、工况和不确定性方法 |
| 智能工作流 | 监测、比较、报告、审核Agent | 专业提示词、工具权限、人工评价规则 |
| 客户端 | 主题订阅、资料查询、权限和导出 | 客户关注重点、专属研究与定制字段 |

## 2. Industry Pack行业知识包的标准模板

| **章节** | **应包含的行业内容** | **例子** |
|---|---|---|
| 行业定义与分类 | 细分产业、产业链、技术和产品边界 | 气体分离膜；电池安全传感 |
| 重要研究主题 | 研究方向、问题库、技术成熟度 | 混合基质膜；内置传感诊断 |
| 核心企业与生态 | 产品商、设备商、科研团队、服务商 | 材料企业、系统商、大学团队 |
| 技术性能字段 | 行业指标、单位、工况和可比规则 | 渗透性/回收率；响应时间/精度 |
| 政策标准 | 地区、规范、状态和适用产品 | 燃气质量；电池安全相关标准 |
| 应用市场 | 客户、项目、工况和采购关系 | 沼气提纯；储能电芯制造 |
| 研究模板 | 竞争、科研、技术路线、经济性 | 技术对标报告、市场机会分析 |
| 数据及许可 | 来源清单、授权、更新时间和质量 | 官方产品资料、论文、专利元数据 |

## 3. 行业包对照：四个典型领域

| **内容** | **膜与气体分离** | **电池与能源** | **LCA与低碳** | **生物制造/农业** |
|---|---|---|---|---|
| 核心技术对象 | 膜、组件、气体流程 | 电芯、传感器、BMS | 活动数据、因子、系统边界 | 生物过程、装置、工艺 |
| 重点指标 | 渗透、选择性、纯度/回收率 | 精度、寿命、响应、SOH | 碳足迹、能耗、数据质量 | 产量、转化率、能耗 |
| 主要信息源 | 科研、膜企业、工程项目 | 科研、电芯厂、标准、专利 | 标准、数据库、行业统计 | 科研、装备、农业与政策 |
| 主要客户 | 材料商、设备商、工程企业 | 电芯厂、系统商、研究机构 | 品牌、咨询机构、园区 | 生产企业、行业机构 |
| 关键研究风险 | 不同层级工况不可比 | 实验/电芯级数据不能混同 | 边界和数据许可不一致 | 季节、品种、系统条件差异 |

## 4. 案例A：某膜技术企业作为膜分离行业包的应用示例

某膜技术企业可以使用“气体分离与先进膜技术 Industry Pack”来研究全球材料与组件、竞品、工程技术、数字孪生科研、政策及下游市场；其现有数字孪生工作产生的外部技术追踪需求，可通过M01和M04形成持续研究主题。该示例展示行业知识包怎样服务一位真实工业客户，而不意味着平台专属于某膜技术企业，也不包含客户内部模型或数据的默认共享。

| **行业模块** | **气体分离行业包字段/关注** | **典型服务成果** |
|---|---|---|
| 科研前沿 | 膜材料、分离性能、研究机构、实验工况 | 技术雷达、科研团队图谱 |
| 竞争产品 | 膜制造商、组件型号、工作条件 | 产品Atlas、竞品性能对标 |
| 工程应用 | 工艺流程、纯度、回收率、能耗 | 技术路线与工程案例 |
| 数字技术 | 膜组件建模、数字孪生、混合模型 | Digital Twin Technology Watch |
| 政策市场 | 生物天然气、CO₂等具体应用 | 政策与产业项目研究 |
| 综合分析 | 技术适用性、经济性与竞争影响 | 结构化专业研究报告 |

## 5. 案例B：迁移到电池与能源技术情报

技术模块与工作流不变，行业包替换为电池传感、诊断、热安全、储能设备及相关技术路线。主要实体可包括电芯厂、系统商、BMS公司、传感方案及研究团队。性能字段从分离效率转为传感厚度、响应速度、精度、环境适用范围、容量影响或验证等级，不能简单沿用膜产品评价规则。

## 6. 案例C：迁移到LCA与可持续性研究

行业包围绕产品环境足迹、活动数据、排放因子、标准、生产过程及区域差异建立。比较重点是功能单位、系统边界、数据来源、代表性和不确定性。对于羊绒等具体场景，可加入牧场—地块—批次等专业关系；然而这类客户专属原始数据及商业数据库的授权边界必须独立管理。

## 7. 案例D：迁移到政府与咨询客户

同一行业包可以服务不同客户类型：制造企业关注竞争产品与研发；咨询公司关注有证据的数据与标准化图表；政府或园区关注区域产业链、重点企业、政策、项目与技术趋势。需要改变的是产品组合、研究尺度、权限和审查要求，而非重新创建所有信息源和软件组件。

# VIII｜商业模式、成熟度与长期经营边界

## 1. 产品化与商业模式

| **收入模式** | **主要内容** | **适合对象** | **规模化条件** |
|---|---|---|---|
| 行业情报订阅 | 主题雷达、重点对象和变化监测 | 企业、研究团队 | 数据与更新可复用 |
| 专业数据授权 | Atlas、字段、产品/企业/研究数据 | 咨询、软件伙伴 | 有合法许可和标准字段 |
| 研究工作空间 | 用户、权限、Agent、历史研究 | 多人员团队 | 使用稳定与维护可控 |
| 专题研究 | 竞争、技术经济性、政策和市场分析 | 企业、政府、咨询 | 研究方法和底层证据可复用 |
| 数据API / OEM | 领域知识接口及嵌入式研究能力 | 平台和企业软件伙伴 | 技术、许可及可靠性条件成熟 |
| 行业知识包 | 新行业知识、评价和研究模板 | 不同产业客户 | 行业配置成本可控 |

## 2. A业务产品成熟度：四个维度

| **维度** | **核心判断** | **可能的验证证据** |
|---|---|---|
| T 技术成熟度 | 功能、检索、指标、证据和更新是否可靠 | 质量测试、纠错率、稳定性 |
| U 用户使用价值 | 客户是否持续阅读、查询、引用或使用成果 | 真实工作流、重复使用和反馈 |
| R 可复用性 | 是否能够迁移第二家客户和第二行业 | 行业包重用率、配置工作量 |
| E 经济可持续性 | 数据、审核、运维与交付成本是否合理 | 行业包维护、数据许可及单位交付成本 |

一个产品拥有可演示页面，不代表客户认可研究价值；已经有一个付费专题，也不代表可复制。建议分别记录四维状态，而非只给出单一成熟度分数。

## 3. 成本结构与风险

| **成本类别** | **主要来源** | **控制思路** |
|---|---|---|
| 数据许可成本 | 商业数据库、全文、标准及API | 按授权使用；先明确必须的数据再采购 |
| 专业研究成本 | 领域专家、核查、报告与持续判断 | 结构化复用，避免每次从零研究 |
| 软件与AI成本 | 存储、检索、模型调用、Agent、部署 | 共用基础能力，设置用量和权限 |
| 行业知识建设 | 指标、术语、市场、评价规则与案例 | 聚焦真实高价值领域，逐步拓展 |
| 客户交付与支持 | 权限、培训、专题、更新与维护 | 标准产品与专项研究分层 |
| 质量与责任成本 | 专业错误、数据许可、合规和保密 | 来源可追溯、人工审核、法律边界 |

## 4. 商业判断与边界

> **▪** 不因某个行业研究需求就自动建设全行业、全地区、全企业的数据库；每个行业知识包需有明确覆盖对象和使用问题。
>
> **▪** 不将“报告自动化”作为唯一差异化，也不将人工咨询完全排除；关键是形成可积累的研究方法与专业资产。
>
> **▪** 不以知识图谱节点数、论文数量、Agent数量等表面规模替代真实客户使用和技术准确度。
>
> **▪** 不将所有客户的知识资产合并；客户数据、背景IP、商业数据库与公开知识严格分类。
>
> **▪** 不预设所有客户必须购买整套平台；允许数据、专题、软件和API按照不同需求独立销售。

## 5. 业务评价指标

| **指标组** | **推荐观察指标** | **代表的管理问题** |
|---|---|---|
| 内容质量 | 来源完整率、数据核实率、条件缺失率 | 结论是否可信 |
| 知识积累 | 结构化对象、可更新技术档案、复用研究模板 | 是否积累而非重复劳动 |
| 客户使用 | 活跃研究主题、重复查询、成果引用、续用 | 客户是否获得长期价值 |
| 复制效率 | 第二客户配置工时、第二行业适配成本 | 产品是否可迁移 |
| 专业分析 | 可比性审核通过、专家修订、争议记录 | 是否真正具备专业深度 |
| 经济性 | 每行业包维护成本、数据成本、客户支持工作量 | 是否能够持续经营 |

# X｜结论：A业务的长期产品形态

> **体系总述**
>
> 专业研究模块提供能力；共享数据与证据体系保障可靠性；标准产品提供可使用的功能；行业知识包提供技术深度；客户工作空间承载具体需求。某膜技术企业只是膜分离行业包的一个应用示例，同一框架可服务电池、LCA、先进材料及其他技术密集型行业。

这套业务不应被定义为自动写行业报告的工具，也不应被限制为某家客户的专属智库。长期竞争力来自对特定技术和产业的理解、能够核查的专业数据、合理的比较方法，以及贯穿科研、产品、工程、政策和市场的持续知识积累。

对不同客户，不必改变基础架构：制造商获得竞品与研发情报，咨询机构获得数据和研究工作流，政府及园区获得产业图谱和政策分析，科研机构获得技术前沿与创新生态。对不同行业，需要调整的是专业知识包与评价规则。

因此，本业务应定位为一个能够随着专业行业知识积累持续发展、支持多种客户和产品交付方式的产业科技智库与专业情报平台。
