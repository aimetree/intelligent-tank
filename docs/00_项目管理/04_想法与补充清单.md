## 怎么用

| 步骤 | 成员做什么 | Claude 做什么 |
|---|---|---|
| 1 收集 | 任何一次对话里想到什么，直接说 | 记成一条放进第 1 节：写明提出人和日期，保留原话，编号接着往下排 |
| 2 批准 | 说“批准 I-05、I-07”，或者说“过一遍清单”逐条定；直接改本文里的勾也可以 | 把批准的条目移到第 3 节并写明批准人；只需要点头的建议，直接记入《决策记录》 |
| 3 细化 | 看任务卡，改到满意 | 把批准的条目展开成任务卡：目标、范围（做什么、不做什么）、产出、验收标准、前置条件 |
| 4 收尾 | 确认完成，或者说先放一放 | 完成的移到第 5 节，搁置或否决的移到第 6 节，都保留记录 |

- 项目由两位成员共同完成，两人共用同一个账号（D-22）。谁在对话中批准就记谁；是否有必须两人都同意的事项，待定（Q-23）。
- Claude 不催批准。只有成员问起，或者当下的话题正好相关时，才提清单里的条目。
- 第 2 节是 Claude 从现有资料里整理出的候选事项，供成员挑选，不是已定计划，可以改、删、合并。
- 每条只写一两句。背景在方括号的编号所指的地方：Q 见《待决问题》，S 和 D 见《决策记录》。
- 新条目的写法：`- [ ] **I-编号　标题**　一句话说明。〔提出人，日期〕`

## 2. 候选事项（Claude 整理，供挑选）

### 2.1 等成员点头的建议（勾选即同意，直接记为决定）

- [ ] **I-01　交付单元**　每个主题交付三件东西：核验过的证据表、针对客户问题的判断、后续变化记录；报告只是展示形式。〔S-02〕
- [ ] **I-02　三组对照验证**　样品用三组对比来检验：AI 独立完成、AI 加我们的流程、再加专业核验与客户背景；由对方盲评，同时记工时和成本。〔S-03〕
- [ ] **I-03　内部计划可以排期**　“对外方案不写实施计划”只约束对外材料，本 Project 内部的路线图可以有阶段和排期。〔S-07〕
- [ ] **I-04　先统一内部口径**　建数据结构之前，先定一份内部统一的能力编号、证据类型和对象模型；已成稿的对外方案不改。〔S-06〕
### 2.2 进入阶段 1（样品）之前要定的

- [ ] **I-05　对外接触的顺序**　先把方案发出去；先聊出对方的具体问题、做出样品再谈；还是方案和样品一起给。〔Q-21〕
- [ ] **I-06　两个样品的主题与先后**　学术、企业两个方向各用什么主题，谁先做，是否并行。〔Q-22，D-17〕
- [ ] **I-07　样品验证方案**　主题边界、证据表字段、检索与核验规则、对照测试的做法和评分表。〔《路线图》阶段 1〕
- [ ] **I-08　专业核验的安排**　哪些内容成员自己能判断，哪些要请外部专家；盲评请谁来做。〔Q-18〕

### 2.3 业务设想（想到多少记多少）

- [ ] **I-09　首批客户画像**　谁买、谁用、他们现在怎么完成这件事、用了 AI 之后还缺什么。〔Q-04、Q-05、Q-06〕
- [ ] **I-10　服务规格与定价设想**　更新周期、覆盖范围、核验深度、修改次数、责任边界、价格区间。〔Q-08、Q-12〕
- [ ] **I-11　两份对外方案发出前的检查**　企业版和学术版方案是否要按“样品先行”的思路调整后再发。〔D-16，Q-21〕
- [ ] **I-12　品牌与产品命名**　独立的智库产品品牌叫什么。〔Q-13〕
