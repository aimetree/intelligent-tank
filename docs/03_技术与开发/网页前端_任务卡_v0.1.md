## 2. 这个对话已经做好的：数据导出

`tools/export_site_data.py`（有测试 `tools/tests/test_export.py`，已加进 GitHub Actions）。前端只读它导出的九个 JSON 文件，不读 `data/` 的目录结构。以后有了后台，接口返回的就是这几个文件的样子，前端不用改。

```bash
python3 tools/export_site_data.py --out site-data                       # 给内部看：含原文片段等只留内部的字段
python3 tools/export_site_data.py --out site-data --audience external   # 对外：去掉内部字段，只留可对外并且至少人工已核的证据
python3 tools/export_site_data.py --data tools/tests/example --out site-data   # 用虚构的示例数据，五页都有内容，开发时用这个
```

| 文件 | 里面是什么 |
|---|---|
| `meta.json` | 文件写法的版本 `format`、给谁看、数据版本（提交号）、规格版本、各类条数、校验问题 |
| `topics.json` | 每个题目的题目卡和指标字典。指标、条件、分类维度的名字都从这里取，前端不写死任何一个指标（D-03） |
| `sources.json` | 来源登记和样品登记 |
| `entities.json`、`relations.json` | 实体、关系 |
| `evidence.json` | 证据 |
| `comparisons.json` | 可比组、描述、复核单 |
| `logs.json` | 变化记录、工作记录 |
| `labels.json` | 代码对应的中文名 |

字段的含义见《数据结构_字段规格》v0.3。仓库里的真实数据现在有 1 个来源、91 条证据，还没有可比组。
