## 0. 先看这一页

### 0.1 一句话

证据库是仓库里的一组数据文件（D-30）。十类数据对象（D-49）里证据是核心：一条证据是一个对象的一个指标（或一个事实项），在一组条件下，从一个来源的一处取到的一个值或一句陈述，带证据类型、核验状态和风险档。v0.2 在 v0.1 上加了四样东西：来源文件里的**样品登记**（来源里出现的每一张膜，带分类和角色）；指标字典里的**事实项**（专利、政策法规、报告、资助这些非学术内容要抽的项）；来源上的**文件属性**（专利、政策法规、标准、资助记录的著录项目和状态）；一张新附表**复核单**（专业复核逐条记确认还是修改）。

### 0.3 十类对象和两张附表

| 对象 | 编号 | 记什么 | 放在哪（建议） |
|---|---|---|---|
| 题目卡 | TOP | 问题、范围、层级、时间窗、哪些来源类别算证据、分类维度 | 每个题目一个文件 |
| 指标字典 | 用键名 | 条件项、指标、事实项、可比规则 | 每个题目一个文件。内容是《阶段1_样品验证方案》第 4 节的试做版，试做后由 Kai 定稿（D-72） |
| 来源 | SRC | 我们实际读到的一份文件：身份、版本、怎么取得的、许可、怎么处理的；非论文类的著录项目和状态 | 一个来源一个文件 |
| 实体 | ENT | 机构、材料族与技术类别、产品、专利族、应用与项目、政策标准 | 一张表 |
| 证据 | EV | 数值或陈述、条件、层级、类型、出处位置、原文片段、核验状态、风险档 | 跟它的来源放在同一个文件里 |
| 关系 | REL | 实体之间、来源与实体之间的关系，每条带出处或标明是推断 | 一张表 |
| 可比组 | CMP | 放在一起比的一组证据、档别、归一化方法、基准膜 | 每个题目一张表 |
| 判断 | ASM | 现阶段只用描述一层，就是数据概览里的陈述 | 每个题目一张表 |
| 变化记录 | CHG | 什么变了、为什么、影响到谁 | 只追加的日志 |
| 工作记录 | LOG | 谁做了什么、工时、调用成本、模型与模板版本 | 只追加的日志 |

两张附表不是新的对象类别，是流程里某一步留下的登记：报告登记（RPT，展示这一步）和复核单（RVW，专业复核这一步）。样品登记是来源文件的一部分，不是对象。

- 公共证据与客户专属内容分开存（D-39）。
- 受版权限制的全文、付费库内容、对方的保密资料不进仓库。成员下载的原文放在 Project 的文件区，不进仓库、不进证据库（D-107）。
- 证据按来源分文件，样品登记也放在来源文件里：抽取、人工核对、改分类都是一篇一篇做的，一次只动一个文件；两个对话同时录不同的论文，不会改到同一个文件。

### 1.2 文件格式（建议，Yu 定）

不变：JSON，两个日志用 JSON Lines；UTF-8，中文不转义；缩进两格，每个字段一行。给人看的表格文件由脚本导出，不手工维护。比较见 v0.1 第 1.2 节。

### 1.3 字段名、枚举和语言

- 字段名用英文小写加下划线，枚举值用英文代码。中文名和英文名放在 `labels.json`，看板和中英两版报告（D-46）都从这里取显示名。
- 题目卡和指标字典自己定义的取值（分类维度的取值，分类型条件和指标的允许取值）也用英文代码，显示名放 `labels.json` 的 `values`，按维度、条件或指标的键分开；单位的显示写法在 `units`，中英文不一样的（如 `cycles`：次、cycles）写 `zh`、`en` 两项。仓库里题目卡和指标字典用到的取值和单位都要有显示名（`tools/tests` 里有测试）。
- 已定（D-66）：证据库里我们自己写的文字（转述、备注、定档的理由、数据概览）先写中文，出英文版时再补同名加 `_en` 的字段；材料名、指标名这类术语保留英文原词。

### 1.4 编号

| 对象 | 写法 | 例 |
|---|---|---|
| 题目、来源、实体、关系、可比组、判断、变化、工作记录、报告、复核单 | 前缀加六位数字 | `SRC-000123`、`RVW-000004` |
| 证据 | `EV-来源序号-三位以上的序号` | `EV-000123-007` |
| 指标、事实项、条件项、可比规则、分类维度 | 英文键名，在一份字典或题目卡里不重复 | `energy_efficiency` |
| 样品 | 原文里的样品名，原样抄，在一个来源里不重复 | `ZW-40%`、`6f-abSPI-60` |

复核单的 RVW 是新加的前缀。其余同 v0.1：编号由脚本分配，取现有最大号加一，一经分配不复用；记录不删除。

### 1.5 日期、数值、缺失

- 日期写 `YYYY-MM-DD`；来源的发布日期和文件属性里的日期可以只到月或年，页面没写就填 `未注明`。
- 数值保留原文写法：`value_reported` 是字符串，原样抄；`value_std` 由脚本算。
- 条件的取值：要么是 `reported`（原文写法，必填）加能解析出的 `value`、`unit`；两端的值（如截止电压的上限和下限）另填 `low`、`high`（v0.2 新加）；要么是 `not_reported`、`not_applicable`。“室温”照抄，不换成数字。
- 缺失分三种，不混用：原文没写 `not_reported`；不适用 `not_applicable`；还没填就是字段不出现。原文没写的不猜、不补。
- 我们自己算出来的量（换算值、与基准之比、选择性的我们自己的算法、能量效率由另两项相乘）不作为证据入库，由脚本在出图出表时算，标“换算值”。

### 1.6 操作人

成员写 `kai`、`yu`；外请的复核人用代号，如 `expert-01`；AI 写 `claude`；脚本写 `script`。只有人能把核验状态改到“人工已核”及以上、给可比组定档、做专业复核、确认关键合并与关键关系、核对登记内容（D-49）。成员下载的文件不记是谁下载的（D-108）。

### 1.7 版本

数据版本就是提交号。每条证据另有 `record_version`。本规格的版本记在 `data/meta.json` 的 `spec_version` 里，现在是 `0.3`。

v0.3 加：版本和迁移的规矩。

- schema 的 `$id` 末尾是规格的版本号（`urn:intelligent-tank:schema:0.3`）。脚本要的就是这一版的数据。
- 数据的 `spec_version` 和 schema 的版本不一样，校验报错（V-00），话里写明该怎么办：数据旧，跑迁移脚本；数据比脚本新，先更新脚本。版本号按数比大小，0.10 比 0.9 新。看板顶上也照样写出这一条。
- 每改一次 schema，版本号往上走一步，并在 `tools/migrate.py` 里登记一步：从哪一版到哪一版、改了什么、怎么把旧数据改成新写法。数据的写法没变、只是规格往上走的，也登记一步，这一步不动数据。步子一步接一步，不跳。
- 迁移先在一份临时的拷贝上改，改完校验一条问题都没有才写回；有问题就一个字也不写。只写变了的文件，没变的一个字节都不动。
- 迁移只改写法，不改意思：不新增证据、不改数值、不改核验状态。要改意思的是数据修订，照常记变化记录。
- 两份日志只在末尾加（V-72），迁移不碰。所以日志的字段只能加可选的；会让旧的行读不进来的改法不许做。
- `data/schema/`、`data/templates/` 不是数据，迁移不读不写。schema 手工改，模板由 `tools/make_templates.py` 生成。
- 仓库的 `data/` 和示例数据 `tools/tests/example/` 各迁一次。以后有了客户专属区，每个区各迁一次。
- 迁移不另记工作记录，提交记录就是记录。

## 2. 枚举

### 2.1 已定的四套口径

**层级 `level`**（D-10）：`material` 材料；`component` 组件或器件；`system` 系统。这三层的数不直接比。v0.2 另加三个值，都不参与对标（V-40）：`product_supply` 产品与供应、`compliance` 合规（指标清单里这两组指标不属于三层，只在一览表里列出，D-67）；`none` 不分层（政策条文、资助信息、报告里的说法这类内容）。

**证据类型 `evidence_type`**（D-32）　六类不变：`verified_fact` 已核实事实；`company_claim` 企业声明；`third_party_analysis` 第三方分析；`experimental` 实验数据；`model_simulation` 模型与模拟结果；`expert_judgment` 专业判断。非学术来源的证据按这句话本身是什么来定（方案 3.8 第 2 条）：

| 内容 | 证据类型 |
|---|---|
| 专利的权利要求写了什么；政策法规和标准的条文；官方统计；资助项目记录 | 已核实事实 |
| 专利实施例里的数 | 实验数据（导出时显示“专利实施例，未经同行评议”） |
| 报告里机构自己的估计、评估、目标和预测 | 第三方分析 |
| 报告里写明由模型算出的结果 | 模型与模拟结果 |
| 报告里转述企业的说法；厂商规格书、产品页、上市申报材料里的一切 | 企业声明（D-64，V-32） |

**核验状态 `verification_status`**（D-32）：`pending` 待核；`machine_checked` 机器已核；`human_verified` 人工已核；`expert_reviewed` 专业已复核；`disputed` 存疑；`void` 作废。含义和谁能给同 v0.1。

**可比档 `tier`**（D-49）：`direct` 直接可比；`conditional` 条件化比较；`reference` 参考性资料；`insufficient` 数据不足。

**状态 `doc.status`**　专利的法律状态，政策法规和标准走到哪一步。字段：`stated`（照数据库或官方页面原样写，必）、`checked_in`（在哪里查的，必）、`checked_at`（查的日期，必）、`stage`（进程，只用于政策法规和标准）、`events`（按日期排的事项，每项 `date`、`summary`、`locator`）、`next_step`（`summary`、`expected`、`locator`）。

- 专利的法律状态只照数据库原样写，不填 `stage`，不作解读，不作侵权和自由实施的判断（D-10，方案 3.8 第 6 条）。

- 报告和看板里政策和标准的“按日期排的事项表”（D-99）从 `events` 取。

**为什么记在来源上，不记成证据**　著录项目和状态说的是这份文件本身，和论文的作者、刊名、撤稿状态是一回事，v0.1 就把来源状态放在来源上。问题七至十要的“保护什么”“规定了什么”“报告给了哪些数”“与膜有关的内容”记成证据（事实项或指标），带出处位置，照常核验。登记内容的人工核对另记 `record_verified_by`。另一种做法是著录项目也逐项记成证据，见第 9.1 节。

#### 3.3.2 版本、更正、付费、只登记

- **预印本和正式版**　两条来源，`version_of` 互相指向。照 E7 以正式版为准；正式版不开放时照 D-105：取数照预印本，正式版只到题录（`access_route` 为 `metadata`），筛选结果写排除、原因写 E7。全量时怎么办，试做后随指标字典请 Kai 定。
- **更正声明**　原来源 `status` 改 `corrected`；更正声明单独登记，`corrects` 指向原来源。更正改到的数：原证据作废，`superseded_by` 指向从更正声明里取的新证据，记一条变化记录（`kind` 为 `source_change`，`trigger_source` 指向更正声明）。
- **学位论文**　按章取舍（《补充 2》）：综述章不收，实验章和附录并成一条来源，写进 `parts`；标为待投稿的章节写进 `watch`，发表后与期刊论文去重（E7，`duplicate_of`）。
- **付费**　`paid.purchased` 为假的，只能用公开部分（`access_scope` 不能是 `full`，`access_route` 不能是 `purchased`），并写评估单在哪里（D-56 第二条、D-98，V-13）。
- **只登记**　不开放的论文只登记题录和膜的类别（D-68）：`access_scope` 为 `metadata_only`，膜的类别写在 `topics[].facets` 里，判断不了的写 `unclear`，`fluorine_basis` 写 `title_abstract`。只到题录的来源不出证据（V-13）。

### 3.4 样品登记（新）

来源文件里加一个列表 `samples`：这个来源里出现的每一张膜一项，研究对象、同文基准、同文对照、作者另拿来对照的膜都登记。

| 字段 | 名称 | 必填 | 说明 |
|---|---|---|---|
| `label` | 原文里的样品名 | 必 | 原样抄，在一个来源里不重复；证据的 `sample_label` 用它 |
| `role` | 在这个来源里的角色 | 必 | `studied`、`baseline`、`control`、`other_reference` |
| `subject_id` | 对应的实体 | 必 | 商业膜指向产品（型号）；实验室样品指向它的材料族；重铸的基准膜指向全氟磺酸的材料族 |
| `baseline_form` | 基准膜的形态 | 条 | 只用于同文基准，必填：原样、预处理过、重铸、原文没写（方案 4.2） |
| `facets` | 分类 | 条 | 实验室样品必填：每一张膜要有的分类维度（3.1.1）。商业膜不写，分类在产品实体上 |
| `notes` | 备注 | 选 | 填料含氟、归类拿不准的理由等 |

- **为什么要它**　D-81 定了每一张膜各有一个材料族和一个传导类型，含氟类别也是按膜判的；实验室样品默认不建实体（v0.1 第 3.4 节），分类就没有地方记。样品登记放在来源文件里，改分类只动一个文件；试做后材料族和传导类型定稿时（D-81），重新归类也只动样品登记。
- **同文基准**（D-71，问题三）是同一篇论文里的全氟磺酸商业膜，或重铸的全氟磺酸膜。只跟自己没改性的原膜比的，原膜记 `control`，不算基准。作者另拿来对照的非全氟磺酸商业膜（如附 B 第 5 篇的 FAP-450）记 `other_reference`，它的数照样收（D-81），不算基准。
- **证据怎么对上**　实验室样品的证据必须写 `sample_label`，并在样品登记里；证据的 `subject_id` 必须等于样品登记里这个样品的。来源里不止一个样品时，证据都要写 `sample_label`（V-19）。补充材料没有自己的样品登记时，用它所属论文的。
- 一览表“行是膜”（D-67）：一行就是样品登记里的一项。

### 3.5 实体

字段同 v0.1。改的是分类：

- 材料族（`entity_type` 为 `material_class`）记 `material_family` 这一类维度；产品记含氟类别、传导类型这一类（`applies_to` 为 `membrane` 的）。键和取值必须在题目卡里定义（V-08）。
- 题目用到的材料族（实验室样品指向的、产品所属的）要有必填的材料族维度；题目用到的产品要有必填的膜的维度（V-08）。
- `material_class` 也用作技术类别（如“全钒液流电池”），报告里的装机这类数字指向它；不被样品或产品用到的，不要求材料族。
- 实验室样品默认不建实体，分类记在样品登记里；个别样品确实跨来源出现时，再建 `sample` 实体（v0.1）。

#### 3.6.1 风险档（D-80）

人工核对之前由 Claude 给每条证据标好：`risk` 有 `tier`（高、中、低）、`reasons`（理由的列表）、`note`、`set_by`、`set_at`。理由和档别照方案 5.6：

| 理由 | 档 | 脚本能不能从字段推出来 |
|---|---|---|
| `figure_read` 图上读数 | 高 | 能：`obtained_from` 为图上读数 |
| `extraction_mismatch` 两遍抽取不一致 | 高 | 能：`double_extraction` 为 `resolved` |
| `machine_check_failed` 机器核对没通过 | 高 | 能：`machine_check` 里有 `fail` |
| `outlier` 数值离群 | 高 | 不能：门槛试做时定 |
| `unit_converted` 经过单位换算 | 中 | 能：原文单位不是标准单位，并且换算过（照原文记、不换算的单位不算） |
| `conditions_elsewhere` 条件和数值不在原文的同一处 | 中 | 能：写了 `conditions_locator` |
| `multiple_samples_or_tables` 同一来源里有多个样品或多张表 | 中 | 能：样品登记多于一项，或证据里出现不止一个样品名、一张表 |
| `from_supplement` 取自补充材料 | 中 | 能：来源是补充材料 |
| `qualified_value` 原文用了“约”“高于”这类限定 | 中 | 能：`value_qualifier` 不是 `eq` |
| `other` 其他 | 不限 | 要写 `note` |

校验（V-31）：人工已核及以上必须有风险档；推得出的理由都要列上；档别不能低于理由里最高的那一档（可以往高标，不能往低标）。推理由的函数在 `tools/validate.py` 里，抽取时可以拿来先填。

## 4. 核验状态怎么走

v0.1 的六条照旧。v0.2 加两处：

1. 正常的路：待核 → 机器已核 → **标风险档** → 人工已核 → **用复核单做专业复核** → 专业已复核。试做批次全部人工核对（D-80），风险档也要标，用来量三档各自的错误比例。
2. 风险档在人工核对之前标好，人工核对时不改；核对发现标错了（比如漏了一个推得出的理由），改了要记一条变化记录。

## 6. 导出给对外报告的证据表

报告附录只放正文引用到的证据，每条一行；全部证据另做成一个数据文件，随报告一起给（D-29、D-102）。两样用同一套列。

| 对外的一行里有 | 取自 |
|---|---|
| 证据编号；对象；层级；指标或事实项 | `id`；实体名称加 `sample_label`；`level`；显示名 |
| 数值、限定符、单位；范围或误差 | `value_reported`、`value_qualifier`、`unit_reported`，标准单位下的值；`range_*`、`uncertainty` |
| 全部必填条件 | `conditions`，原文没写的显示“未报告” |
| 证据类型；取得方式；标注 | `evidence_type`；`obtained_from`；`display_flags()` 给出的标注（新）：预印本，未经同行评议；学位论文；专利实施例，未经同行评议；企业声明；图上读数（带读数误差）；仅摘要；付费来源，只用了公开部分 |
| 来源；来源类别；法域 | 题名、作者或发布机构、刊名、发布日期、DOI 或网址、版本；`source_type`（新）；`jurisdiction`（新） |
| 出处位置；转述 | `locator`；`summary` |
| 取得日期；最近核验日期；核验状态 | `obtained_at`；`verified_at` 或 `expert_reviewed_at`；`verification_status`。数据文件里还没核过的照实带状态（D-102 的默认做法） |
| 适用范围与限制；所在可比组和档别；对应的问题 | `scope_note`；由可比组反查；`questions`（新） |

只留内部、不导出：`snippet`、`conditions_snippet`、`internal_note`、`machine_check`、`risk`（新）、各个操作人字段、`entry_method`、`double_extraction`，复核单，以及工作记录和变化记录里的内部更正。

看板首版五页（D-31、D-61、D-111）用到的对象：总览用来源、证据、变化记录、工作记录的统计；证据表用证据加来源，按来源类别筛选；对标视图用可比组加证据；数据概览与缺口用描述、一览表（样品登记加证据）、`core_check`；非学术来源用专利、政策法规和标准、产业和市场的数字、科研资助四块，取自来源的文件属性和带 `questions` 的证据。

### 9.2 给 Kai 的

这一版要落的都出自已定的决定，起草时没有碰到要 Kai 另定的口径，所以没有出点选题。照已定决定落下来时有几处读法，写在这里。Kai 2026-11-14 四处都认可了（D-124，J-157）：

1. **条款禁止 AI 的来源**（V-12）。D-56 第三条是改由人读；D-89 定了现阶段下载上传文献不因法规上的顾虑而停，D-92、D-104 照此让 Claude 读了 SSRN 预印本和麦肯锡参与的报告。规格照这个做法写：成员下载或代查之后可以交给 AI 读，读取工具直接读不行。进入付费试点之前随律师清单重看（D-57）。
2. **同文基准只认全氟磺酸**（3.4）。依据是问题三“与同一篇论文里的全氟磺酸商业膜相比”和 D-71。作者另拿来对照的非全氟磺酸商业膜（如附 B 第 5 篇的 FAP-450）记作“另拿来对照的膜”，数照收，不算基准、不算比值。
3. **IN-39 的证据类型记“专业判断”**（3.2.1）。它是我们按结构和 OECD 的定义判的，六类里只有这一类说得通；这只是归类，不是评价（D-60）。
4. **事实项不是指标**（3.2）。方案 4.3 写了范围扩大后不加新指标；事实项只用来给专利、政策法规、报告、资助这些内容分块，不进一览表，不进可比组。

试做后随指标字典、风险标注一起请 Kai 定的（不是现在）：

- 风险档里“同一来源里有多个样品或多张表”算中档（方案 5.6）。论文都有同文基准，至少两个样品，所以论文里的数几乎都会到中档，低档主要剩规格书、只有一个实施例的专利和摘要。试做后看三档各自的错误比例时要记得这一点；要不要把这一条收窄成“两个以上研究对象或两张以上的表”，到时随“全量要不要按风险核对”一起定（D-80）。
- 事实项的清单（3.2.1），随指标字典定稿。
- 部分含氟同时符合几种子类时取哪一种（3.1.1），随材料族定稿（D-81）。
