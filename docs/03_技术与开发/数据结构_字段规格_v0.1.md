## 0. 先看这一页

### 0.1 一句话

证据库是仓库里的一组数据文件（D-30）。十类数据对象（D-49）里证据是核心：一条证据是一个对象的一个指标，在一组条件下，从一个来源的一处取到的一个值，带证据类型和核验状态。其余九类，有的给它定口径（题目卡、指标字典），有的说明它从哪来、指的是谁（来源、实体、关系），有的是在它上面做的事（可比组、判断），有的记过程（变化记录、工作记录）。

### 0.2 十类对象

| 对象 | 编号 | 记什么 | 放在哪（建议） |
|---|---|---|---|
| 题目卡 | TOP | 问题、范围、层级、时间窗、哪些来源类别算证据 | 每个题目一个文件 |
| 指标字典 | 用键名 | 指标、条件项、可比规则 | 每个题目一个文件。内容在 T-04 起草，要 Kai 确认 |
| 来源 | SRC | 我们实际读到的一份文件：身份、版本、怎么取得的、许可、怎么处理的 | 一个来源一个文件 |
| 实体 | ENT | 机构、材料类别、产品、专利族、应用与项目、政策标准 | 一张表 |
| 证据 | EV | 数值或陈述、条件、层级、类型、出处位置、原文片段、核验状态 | 跟它的来源放在同一个文件里 |
| 关系 | REL | 实体之间、来源与实体之间的关系，每条带出处或标明是推断 | 一张表 |
| 可比组 | CMP | 放在一起比的一组证据、档别、归一化方法 | 每个题目一张表 |
| 判断 | ASM | 描述或判断、依据清单 | 每个题目一张表。整类可选，等 Kai 定 J-61、J-62 |
| 变化记录 | CHG | 什么变了、为什么、影响到谁 | 只追加的日志 |
| 工作记录 | LOG | 谁做了什么、工时、调用成本、模型与模板版本 | 只追加的日志 |

另有一张附表“报告登记”（RPT），记每份报告用的数据版本和引用了哪些证据。它不是第十一类对象，是展示这一步留下的登记。

## 1. 通用约定

### 1.1 目录（建议）

```
data/
  meta.json                 规格版本
  labels.json               字段和枚举值的中文名、英文名
  schema/                   字段的机器可读定义（JSON Schema）
  templates/                空白模板，由 schema 生成
  changes.jsonl             变化记录，只追加
  worklog.jsonl             工作记录，只追加
  public/                   公共区：只放来自公开来源的内容
    sources/SRC-000001.json   一个来源一个文件：来源登记，加从它取出的全部证据
    entities.json             实体
    relations.json            关系
    topics/TOP-000001/
      topic.json              题目卡
      dictionary.json         指标字典：指标、条件项、可比规则
      comparisons.json        可比组
      assessments.json        判断（可选）
      reports.json            报告登记
  clients/<客户代号>/        客户专属区：现在没有客户，先不建
```

- 公共证据与客户专属内容分开存（D-39）：对方的背景、对方提供的资料、专属的判断不进 `public/`。
- 受版权限制的全文、付费库内容、对方的保密资料不进仓库（《协作流程》第 6 节；《设计方案》3.2）。对方的保密资料放在哪里还没有定（Q-16）。
- 证据按来源分文件的理由：抽取和人工核对都是一篇一篇做的，一次只动一个文件；两个对话同时录不同的论文，不会改到同一个文件。

### 1.2 文件格式（建议，Yu 定）

字段和规则与格式无关，换格式只改读写。默认建议用 JSON。

| 格式 | 好处 | 代价 |
|---|---|---|
| JSON（建议） | 不依赖额外的库；类型严格，不会把 `2023-05`、`no` 这类值悄悄转成别的类型；嵌套的条件可以直接写 | 不能写注释；人直接读不如 YAML 顺眼 |
| YAML | 人读着顺，多行文字好写，可以写注释 | 要装解析库；类型会自动转换，容易出暗错，要靠校验兜住 |
| CSV | 能直接用 Excel 打开 | 每条证据的条件是不定长的键值，要么塞进一格，要么另开一张长表；多行文字和逗号要转义 |

写法：UTF-8，中文不转义；缩进两格，每个字段一行，这样每次提交的差异能看出是哪个字段变了。两个日志用 JSON Lines（一行一条），只在末尾加。给人看的表格文件（Excel 或 CSV）由脚本导出，不手工维护。

### 1.3 字段名、枚举和语言

- 字段名用英文小写加下划线，枚举值用英文代码。中文名和英文名放在 `labels.json`，看板和中英两版报告（D-46）都从这里取显示名。
- 自由文本（转述、理由、备注）用中文写。要进英文报告的字段可以另有一个同名加 `_en` 的字段，出英文版时再补。这一条牵涉报告怎么出两种语言，见第 9.2 节。

### 1.4 编号

| 对象 | 写法 | 例 |
|---|---|---|
| 题目、来源、实体、关系、可比组、判断、变化、工作记录、报告 | 前缀加六位数字 | `SRC-000123`、`CMP-000004` |
| 证据 | `EV-来源序号-三位以上的序号` | `EV-000123-007`：来源 SRC-000123 的第 7 条 |
| 指标、条件项、可比规则 | 英文键名，在一份字典里不重复 | `energy_efficiency` |

- 前缀沿用《设计方案》6.2 的九个（TOP、SRC、ENT、EV、REL、CMP、ASM、CHG、RPT），工作记录的 LOG 是新加的。
- 编号由脚本分配：取现有最大号加一。一经分配不复用（《设计方案》6.2）。
- 记录不删除。证据作废改状态；实体合并填 `merged_into`；来源撤稿改 `status`。
- 证据编号带来源序号的理由：看编号就知道去哪个文件找；两个对话同时录不同的论文不会抢号。除此之外编号不带含义。

### 1.5 日期、数值、缺失

- 日期写 `YYYY-MM-DD`。来源的发布日期可以只到月或年（`2023-05`、`2023`），页面没写就填 `未注明`。
- 数值保留原文写法：`value_reported` 是字符串，原样抄，保留有效数字；`value_std` 是换算到标准单位后的数，由脚本算。
- 单位用 ASCII 写法：`mA/cm2`、`ohm*cm2`、`mS/cm`、`degC`、`%`，无量纲写 `1`。显示用的符号放在 `labels.json`。
- 缺失分三种，不混用。原文没写：`not_reported`。不适用：`not_applicable`。还没填：字段不出现，必填字段不允许这样。原文没写的不猜、不补（《设计方案》2.6）。
- 我们自己算出来的量（换算值、与基准之比、平均）不作为证据入库，由脚本在出图出表时算。

### 1.6 操作人

成员写 `kai`、`yu`；外请的复核人用代号，如 `expert-01`；AI 写 `claude`，具体模型记在工作记录里；脚本写 `script`。只有人能把核验状态改到“人工已核”及以上、给可比组定档、确认关键合并与关键关系（D-49 的分工）。

### 1.7 版本

数据版本就是提交号（《设计方案》6.2）。每条证据另有 `record_version`，内容每改一次加一。本规格的版本记在 `data/meta.json` 的 `spec_version` 里。

## 2. 枚举

### 2.1 已定的四套口径

**层级 `level`**（D-10）：`material` 材料；`component` 组件或器件；`system` 系统。

**证据类型 `evidence_type`**（D-32）　六类是不同类型，不是高低等级。AI 生成的文字不属于任何一类。

| 代码 | 中文 | 用在哪 |
|---|---|---|
| `verified_fact` | 已核实事实 | 登记簿上的专利状态、标准文本这类有一手来源的事实 |
| `company_claim` | 企业声明 | 厂商规格书、官网、披露文件里的性能、寿命、价格 |
| `third_party_analysis` | 第三方分析 | 综述汇总或转引的数、机构报告里的统计。2021 年以前的文献只经综述引用，记这一类（D-59） |
| `experimental` | 实验数据 | 论文和公开实验测得的结果，包括论文里测商业膜得到的数 |
| `model_simulation` | 模型与模拟结果 | 计算、模拟、情景推演 |
| `expert_judgment` | 专业判断 | 我们或他人依据多项证据作出的推断 |

**核验状态 `verification_status`**（D-32）

| 代码 | 中文 | 含义 | 谁能给 |
|---|---|---|---|
| `pending` | 待核 | 刚录入，未检查 | 录入时的默认值 |
| `machine_checked` | 机器已核 | 脚本确认三件事：标识能解析；原文片段能在来源文本里逐字找到；片段里的数值、单位与记录一致 | 只能由脚本给 |
| `human_verified` | 人工已核 | 人打开原文，确认数值、单位、条件、所指对象无误 | 成员或受托的人 |
| `expert_reviewed` | 专业已复核 | 懂行的人确认层级、条件是否齐全、可比档是否归对 | Kai 或他找的人（D-52） |
| `disputed` | 存疑 | 来源之间矛盾，或原文含糊 | 任何环节，要写说明 |
| `void` | 作废 | 已被更正、来源撤稿或被新版本取代 | 任何环节，要写原因 |

**可比档 `tier`**（D-49）：`direct` 直接可比；`conditional` 条件化比较；`reference` 参考性资料；`insufficient` 数据不足。

| 字段 | 取值 |

## 3. 各对象的字段

### 3.1 题目卡

| 字段 | 名称 | 必填 | 说明 |
|---|---|---|---|
| `id`、`title` | 题目编号、题目 | 必 | |
| `direction` | 方向 | 必 | `academic`、`enterprise` |
| `status` | 状态 | 必 | `draft`、`active`、`closed` |
| `questions` | 要回答的问题 | 必 | 列表，每项 `key`（`Q1`…）和 `text` |
| `scope_in`、`scope_out` | 范围、不包括什么 | 必 | |
| `levels` | 涉及的层级 | 必 | |
| `time_window` | 时间窗 | 选 | `from` 和 `earlier_rule`。学术样品是 2021 年起，更早的只引综述（D-59） |
| `evidence_source_types` | 哪些来源类别算证据 | 必 | 学术样品按 D-56 的六类 |

### 3.2 指标字典

每个题目一份，分三部分，每一项都可以带 `notes`。内容不在本文范围：T-04 起草，由懂行的人确认（D-52）。

| 部分 | 字段 | 说明 |
|---|---|---|
| 整份 | `topic_id`、`version`、`status`、`confirmed_by` | `status` 为 `draft` 或 `confirmed` |
| 条件项 `conditions` | `key`、`name_zh`、`name_en`、`value_kind`、`unit_std`、`allowed_values` | 例：电流密度、电解液里的钒浓度和酸浓度、温度、膜厚、测试方法 |
| 指标 `indicators` | `key`、`name_zh`、`name_en`、`aliases`、`level`、`value_kind`、`unit_std`、`units_accepted`、`allowed_values`、`required_conditions`、`optional_conditions`、`definition`、`status` | `units_accepted` 每项是 `unit` 和换算到标准单位的 `factor`。`required_conditions` 是必须同时记录的条件，证据的校验靠它。分类型指标的例子：成熟度阶梯的五级、是否做到电堆 |

## 4. 核验状态怎么走

1. 正常的路：待核 → 机器已核 → 人工已核 → 专业已复核。
2. 图上读数没有原文片段可比对，机器只查标识。由人复读、写明读数误差后，直接到人工已核（D-34）。
3. 存疑和作废可以从任何状态进入。标成存疑不抹掉之前核到哪一步，核验人和日期保留。分歧解决后改回原来的档，并记一条变化记录。
4. 状态到了人工已核之后再改内容，必须同时记一条变化记录（不无痕修改）。
5. AI 不能把状态改到人工已核及以上。
6. 逐字比对要有来源的文本在手。文本不进仓库，所以比对在抽取的当时做，结果记在 `machine_check` 里。比对之前先做空白和字符的规范化（PDF 抽出来的空格、连字符、上下标常与原文不同），规范化的规则由 Yu 定。

## 6. 导出给对外报告的证据表

报告附录里，每条被引用的证据有完整的一行（D-29）；不放逐字的原文片段，用出处定位加我们自己的转述（D-56）。

| 对外的一行里有 | 取自 |
|---|---|
| 证据编号；对象；层级；指标 | 证据的 `id`；实体名称加 `sample_label`；`level`；指标的显示名 |
| 数值、限定符、单位；范围或误差 | `value_reported`、`value_qualifier`、`unit_reported`，以及标准单位下的值；`range_*`、`uncertainty` |
| 全部必填条件 | `conditions`。原文没写的显示“未报告” |
| 证据类型；取得方式 | `evidence_type`；`obtained_from`。图上读数、仅摘要要显示出来，图上读数带读数误差 |
| 来源 | 来源的题名、作者或发布机构、刊名、发布日期、DOI 或网址、版本 |
| 出处位置；转述 | `locator`；`summary` |
| 取得日期；最近核验日期；核验状态 | `obtained_at`；`verified_at` 或 `expert_reviewed_at`；`verification_status` |
| 适用范围与限制；所在可比组和档别 | `scope_note`；由可比组反查 |

只留内部、不导出：`snippet`、`conditions_snippet`、`internal_note`、`machine_check`、各个操作人字段、`entry_method`、`double_extraction`，以及工作记录和变化记录里的内部更正。

看板首版四页（D-31）用到的对象：总览用来源、证据、变化记录、工作记录的统计；证据表用证据加来源；对标视图用可比组加证据；判断与依据用判断，这一页放什么等 J-61。

### 8.3 与《设计方案》v0.1 第 2.4、2.6 节的出入

都属于实现上的细化，十类对象和四套口径没有动。

### 9.2 留给 Kai（方案类），建议并进 T-04 的题目

这几点 Claude 没有代为决定。规格在这些地方都留了余地，哪种答案都不用改结构。

1. **判断这类对象用不用、用到哪一层。**就是 J-61、J-62，等 Kai 继续。
2. **哪些来源类别算证据来源。**D-56 定了六类。《学术样品_题目收窄方案》第 4 节提到价格可以取自上市申报材料，企业官网的产品页也列有性能数据，这两类不在六类里。算不算，在题目卡的 `evidence_source_types` 里改一下即可。
3. **同一篇论文里的对照算不算“直接可比”。**同一篇论文、同一批测试里，样品和基准膜的条件相同，但原文可能没写全（例如没写温度）。按现在的规则（V-41）进不了“直接可比”。
4. **时间窗对商业膜一侧是否同样适用。**D-59 是接着综述往后做，2021 年起逐篇核对。《题目收窄方案》里商业一侧用到了 2015 年的电堆对比论文。
5. **人工核对算在对照的哪一组。**D-25 里 B 组是 AI 加模板、规则与流程，C 组再加专业复核。成员打开原文核对数值（人工已核）这一步算 B 还是算 C，影响两组的工时怎么记。
6. **自由文本的语言，以及片段的长度。**自由文本先用中文写、出英文版时再补，是否可以；内部留存的逐字片段留多长，属于 D-57 说的要问律师的问题（清单 I-25），本文只按“一句话或表格的一行”来写。

指标字典、条件项和可比规则的内容本来就在 T-04 里，由 Kai 确认，不在这六点之内。
