## 3. 第 1 步：做了什么

| 文件 | 做什么 |
|---|---|
| `tools/ids.py` | 分配编号：取现有最大号加一；读不了的文件也算占着号 |
| `tools/compare_extractions.py` | 两遍抽取的比对。一致的写好 `double_extraction: agree`，可以直接登记；图上读数两遍并排列出，记 `na`；不一致的、只有一遍有的列出来等人裁定；数值挂错了样品的也对得上。陈述型只比有没有、在不在同一处，不比转述的措辞 |
| `tools/check_identifiers.py` | 标识能否解析，写来源的 `id_check`。有 DOI 的到 DOI 注册处查这个号存不存在，不碰出版商的网站；没有 DOI、成员下载或代查的，成员取到了就是存在，不发请求；其余的先看网站的 robots.txt，让自动访问才打开登记的网址。条款禁止自动访问又不是成员取来的不查。没查成的（超时、被拒、robots.txt 不让）不写进数据，列出来等人确认 |
| `tools/machine_check.py` | 机器核对，写证据的 `machine_check`：来源的标识通过了解析；原文片段在来源文本里逐字找得到；数值在片段里，数值后面紧跟着单位的，和记录的单位一致。都过了的从待核改成机器已核，没过的留在或退回待核；人工已核及以上的不动。然后按字段推出风险理由，预填风险档；数值离群、其他这两种由人或 Claude 标，重跑时留着 |
| `tools/textmatch.py`、`tools/store.py` | 共用的比对和读写。比对只放宽排版上的差别（上标、全角、横线的写法、空白、换行、行尾断词），不改字，大小写不放宽 |
| `tools/tests/test_step1.py`、`tools/tests/example_texts/` | 测试，和虚构的来源文本 |
| `.github/workflows/checks.yml` | 数据或脚本有改动时跑校验和两组测试 |

## 3b. 第 3 步：做了什么

| 文件 | 做什么 |
|---|---|
| `tools/derive.py` | 派生值，三种。一、标准单位下的值 `value_std`：原文数值乘上指标字典里这个单位的换算系数，加 `--write` 写回来源文件；照原文记的单位（币种、GW）不算；原文数值的写法认不出的（范围、带单位）不猜，列出来等人处理。二、与同文基准之比。三、派生指标（现在是 IN-16“最高测试电流密度”）。后两种出图出表时现算，不入库，页面上标“换算值” |
| `tools/charts.py` | 图。脚本直接写 SVG，不用图表库（Yu 定了，待编-26）。两种图：一行一个对象的点图；两个量的图。刻度取整；全是正数、最大最小差到一百倍以上时用对数轴；原文给了范围或误差就画出来，图上读数的用虚线；只有同一批测试里同一个样品的点才连线 |
| `tools/compare_view.py` | 对标视图：先算出每个可比组要显示什么，再写成网页 |
| `tools/display.py`、`tools/htmlgen.py` | 从 `build_dashboard.py` 拆出来的两块：取显示名和数的写法；写网页。拆完之后生成的页面逐字节没变 |
| `tools/validate.py`、schema、指标字典 | 认原文数值写法的函数，换算和校验共用；指标加 `derived_from`。两处都是和《字段规格》v0.2 的新出入，见第 4 节第 5、6 处 |

**页面上有什么**

- 对标视图：层级各有各的一块，一次看一层，默认打开第一个有可比组的层级。
- 每个可比组一张卡片：编号和名称，对应题目卡的哪一问；档别、状态、用的可比规则、归一化方法；定档理由和“数据不足”缺什么；一张图；成员的表（证据编号、对象、角色、数值、与基准之比、关键条件和各成员不一样的条件、证据类型、核验状态）；各成员都一样的条件写成一行；没画进图里的成员和原因。
- 一组画什么图：只有一个指标的画点图，一行一个对象；用“与基准之比”的画比值，带一条“基准 = 1”的参考线；两个指标的画两个量的图，一个对象一个点。三个指标以上的不画图，只有表。
- 同一批测试里随条件变化的图：同一来源、同一批测试里，同一个样品在不同条件下（比如不同电流密度）的点连成线，不同样品之间不连。
- 可比性矩阵：这一层里谁和谁在同一个组里、是哪一档；同在几个组里的显示最高的一档，只作参考的成员和谁并排都只算参考。
- 派生指标的表：每个对象在同一批测试里取到的那一条，和它出自哪条证据。
- 点得进去：图上的点 → 成员表里那一行 → 证据表里那条证据；证据表展开后“所在可比组”点得回对标视图里那一组。
- 成员照登记的次序排，不按数值排名，不求平均；专业已复核的点实心，还没复核的空心（《设计方案》6.1，D-60）。

## 3c. 看板的观感

Yu 2026-11-14 17:32 说“可以仿照apple的软件设计风格”（待编-27）。Claude 的理解和自己定的几处，写在《待编入的判断》2h 节。

**改了什么**

- `tools/dashboard/style.css` 重写：浅灰的底上放白色的大圆角卡片；用系统自带的字体；页面导航是分段式的，选中的一段是浮起来的白块、字加粗；按钮、筛选和核验状态、可比档、风险档的标记是胶囊形的；下拉框和查找框是白底细框；钉在顶上的表头半透明；证据编号旁边是一个小箭头，点开以后朝下；用细的分隔线，不用框；强调色只有一种蓝。
- `tools/charts.py` 开头的颜色和字体换成同一套：墨色画基准，蓝色画参与比较的，灰色画只作参考的。网格和坐标轴改成浅色的细实线，同一个样品的连线加粗。
- 顺手改的两处，不属于观感：对标视图的表里，汉字只在标点和空格处换行，一栏不会挤成一个字宽，窄屏上放不下就在自己的框里左右滑；证据和可比组的编号不拆成两行。

**没有改的**

- 页面有哪几块、每块放什么、网页的结构、页面脚本，都没有动。
- 图例的画法：证据类型六个实心形状；核验状态是实心、浅底、空心、虚线四种画法，加存疑、作废；可比档是实心、空心、灰底、虚线。每个记号旁边都有字，颜色不单独表示含义，打印成黑白也看得懂（《设计方案》6.1）。
- 页面是一个文件，打开时不向任何地方发请求；同样的数据生成出来逐字节相同。

**验证到的**

- 加了两项浏览器里的测试：每一处字和它底色的对比度不低于 4.5（WCAG 2 的 AA）；能点的控件不矮于 44 像素。五页、证据全部展开、跳到对标视图的一行，宽屏和手机宽度各量一遍。量法自己也有一项测试。
- 加了一项图的颜色的测试：三种角色的颜色互不相同；记号在底色上的对比度不低于 3，图上的字不低于 4.5；字只用墨色和次要文字的颜色，不跟着数据的颜色走。
- 把样式和图的颜色故意改坏 19 种（字调浅、控件调矮、两种角色用同一种颜色等），这几项测试每次都抓到了。
- 三种角色的颜色用色觉障碍的模拟算过分不分得开：最接近的一对是灰和蓝，红色盲的模拟下色差 18.4，要求是不低于 8。
- Claude 在 Chrome 里截图看过宽屏和手机宽度的各页：总览、证据表、展开的一条证据、对标视图、图例。

**没验证到的**

- 在苹果的设备上是什么样子 Claude 没有看过。Claude 这边只有 Linux 上的 Chrome，那里的字体是另一套；Mac、iPhone、iPad 上用的是它们自带的系统字体，请 Yu 看一眼。Safari 也没有测过；查找框里提示文字的颜色，Chrome 自己的默认就够深，测试分不出我们写的那一条起没起作用。
- 只做了浅色一种外观。系统设成深色时，页面仍是浅色的。
- 要换回原来的样子：还原 `tools/dashboard/style.css`，和 `tools/charts.py` 开头的颜色、字体两处。页面的内容不受影响。
