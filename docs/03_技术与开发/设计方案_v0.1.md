## 0. 先看这一页

### 0.1 一句话

对内 dashboard 和对外报告是同一份证据库的两种展示。先有带出处、带条件、带核验状态的证据记录，再有判断，最后才是图表和文字。报告不另写一套，从证据库生成。

### 0.2 设计要点

| 主题 | 要点 | 详见 |
|---|---|---|
| 总体架构 | 四段：来源 → 证据 → 判断 → 展示。核验状态、版本与变化、许可与隔离、工时与成本四件事贯穿全程 | 第 2 章 |
| 交付内容 | 三件内容（核验证据表、针对问题的判断、变化记录），两个版本（对内 dashboard、对外报告）。内容是一份，两个版本只是展示的范围和形式不同 | 2.3 |
| 模块 | 九个功能模块加两个贯穿模块，每个都写明 AI 做什么、程序做什么、人做什么、不做什么 | 第 3 章 |
| dashboard | 八个页面，首版建议先做四个。做法建议是“数据文件加生成的静态页面”，不建数据库和服务 | 第 4 章 |
| 报告 | 九节结构。图表由数据生成，正文依据判断记录起草，发出前过程序核对和人工复核 | 第 5 章 |
| 可视化 | 一张图只放一个层级；证据类型、核验状态、可比档别用固定图例；不可比的不排名 | 6.1 |
| 可追溯 | 报告里任何一个数，都能逐级追到原文的页、表、图和原文片段；来源被更正时，能反查出受影响的判断和报告 | 6.2 |
| 信息准确 | 十三类错误各有对应的控制手段，设五道关口；人工核对集中在报告要用的那部分数据上 | 6.3 |
| 大模型现状 | 写作和排版已经很强，事实与引用仍是短板；从正文和表格抽数的准确率高，从图上读数明显低；跨文献对齐条件仍不可靠 | 第 7 章 |
| 竞争 | “带引用的 AI 报告”已是各家标配；数据规模、品牌、渠道我们比不过。可验证的增量在条件化对标、逐条核验和跨类型关联，目前都还是假设 | 第 8 章 |
| 分期 | 样品阶段只做最小的一套；数据库、流水线、可登录的看板放到阶段 3 | 第 10 章 |

### 1.2 设计原则

| # | 原则 | 意思 | 出处 |
|---|---|---|---|
| 1 | 证据先于文字 | 任何输出里的数字和论断都指向证据记录；AI 生成的文字不是证据 | 方案01 IV.4 |
| 2 | 一份数据，两种展示 | dashboard 和报告读同一份证据库，不各写一套 | D-26；方案01 V.3 |
| 3 | 条件跟着数据走 | 没有测试条件和层级的数值，不进入比较 | 方案02 §5.2、附录 B |
| 4 | 类型不混，层级不混 | 事实、声明、实验、模型、判断是不同类型，不是高低等级；材料、组件、系统三层不直接比 | D-10；交接《产品与知识架构》§6 |
| 5 | 不能比就说不能比 | 可比性分四档，“数据不足”是正式结论 | 方案02 §5.3 |

| 7 | AI 做量，人对结论负责 | 关键合并、参数核对、可比性、技术结论、重要性判断由人定 | 方案01 IV.6；交接《产品与知识架构》§8 |

## 2. 总体架构

### 2.1 四段流程

```
对方的问题
   │
   ▼
〔定题〕题目卡、指标字典、可比规则
   │
   ▼
〔来源〕检索 → 来源登记（身份、类型、许可、取得方式）
   │
   ▼
〔证据〕抽取 → 证据记录（数值、单位、条件、层级、类型、出处位置、原文片段）
        归并与关联 → 论文—团队—专利—企业—产品，每条关系带出处
        核验 → 机器核对 → 人工核对 → 专业复核
   │
   ▼
〔判断〕可比组与四档可比性 → 判断（结论、成立条件、依据、假设、未知）
   │
   ▼
〔展示〕对内 dashboard：全量，含未核验和存疑的记录
        对外报告：只含达到对外门槛的部分

贯穿全程：核验状态 ｜ 版本与变化记录 ｜ 许可与隔离 ｜ 工时与成本
```

### 2.2 与四层产品结构的对应

四层结构是已定的（D-02）。下表是它在样品阶段落成的样子。

| 四层结构 | 样品阶段落成什么 | 现在不做 |
|---|---|---|
| L1 共享研究与数据底座 | 数据结构；检索与核验规则；抽取和起草用的模板；机器核对脚本 | 采集流水线、数据库、Agent 平台 |
| L2 标准产品 | 两个展示件：对内 dashboard、对外报告 | 雷达、图谱、工作空间、API 等成型产品 |
| L3 行业知识包 | 每个主题一份指标字典、实体与来源清单、可比规则、报告模板 | 覆盖整个行业的知识包 |
| L4 客户工作空间 | 每个客户一份题目卡和背景说明，连同对方提供的资料单独存放 | 账号与权限系统 |

### 2.3 三件交付内容与两个版本

此前的建议是交付三件东西：核验证据表、针对问题的判断、变化记录（S-02）。Kai 把交付定为两个版本（D-26）。本方案的理解：三件是内容，两个版本是展示，两者不冲突。

| 内容 | 是什么 | 在对内 dashboard 里 | 在对外报告里 |
|---|---|---|---|
| 核验证据表 | 每条数据的数值、单位、条件、层级、出处位置、证据类型、核验状态 | 全量，含未核验和存疑的记录，可筛选、可点到原文片段 | 只含报告用到、且达到对外门槛的记录；放在附录或附件（J-02） |
| 针对问题的判断 | 结论、成立条件、依据、假设、不能判断的部分 | 全部判断，含草稿和复核状态 | 通过复核的判断，写成正文 |
| 变化记录 | 新信息改变了哪条证据或判断，为什么 | 完整时间线，含内部更正 | 首份报告只有版本说明；以后各期有“本期变化”一节 |

### 2.4 数据对象（草案，取决于 I-04）

| 名称 | 记什么 | 样品阶段的形态 |
|---|---|---|
| 题目卡 | 要回答的问题、范围边界、涉及的层级和指标；对方的背景另存 | 每个题目一个文件 |
| 指标字典 | 指标名、单位与换算、所属层级、必须同时记录的条件、可比规则 | 每个主题一张表，属于行业包 |
| 来源 | 论文、补充材料、专利、规格书、网页、标准等的身份、版本、取得方式和许可 | 一张表 |
| 实体 | 机构（企业、高校、团队）、材料与技术、产品、专利族、应用与项目、政策标准；带别名 | 一张表 |
| 证据 | 一条数据点或一条陈述，见 2.6 | 一张表，是核心 |
| 关系 | 实体之间的关系，每条带出处；AI 推断的单独标记 | 一张表 |
| 可比组 | 放在一起比较的一组证据、所属的可比档、归一化方法 | 一张表 |
| 判断 | 问题、结论、成立条件、依据清单、假设、未知、复核人 | 每条一段结构化记录 |
| 变化记录 | 什么变了、为什么、影响到哪些判断和报告 | 只追加的日志 |
| 工作记录 | 属于 A、B、C 哪一组、做了什么、工时、调用成本、用的模型和模板版本、发现的问题 | 只追加的日志 |

与交接资料的对应：方案01 的九类对象（企业与机构、技术、产品、研究成果、指标、政策标准、应用项目、证据、研究判断）都在里面，其中前三类和政策标准、应用项目并入“实体”，研究成果记为“来源”，指标记在“指标字典”。新增的是题目卡、可比组、变化记录和工作记录，前两个为条件化对标服务，后两个为变化留痕和三组对照服务。

### 2.5 四套口径

**证据类型（六类，草案）**　各版方案的写法不同（《项目基线》§6.3）。下表是内部口径的草案，右列说明它与各版原写法的对应；对外方案保持原样。

| 类型 | 含义 | 展示时怎么标 | 对应各版原写法 |
|---|---|---|---|
| 已核实事实 | 有可查的一手来源，条件明确。例如登记簿上的专利状态、标准文本 | 给来源和日期 | 方案01 E1；方案02“官方或经核实事实” |
| 企业声明 | 企业自己发布的性能、寿命、案例 | 标“企业声明”，不当作独立验证 | 方案01 E2 的一部分；方案02“企业公开声明” |
| 第三方分析 | 研究机构、行业报告、产业统计 | 写明口径和方法 | 方案01 E2 的一部分；方案02“第三方行业分析” |
| 实验数据 | 论文和公开实验测得的结果 | 带测试条件和样本 | 方案01 E3；方案02“学术研究结果”中的实验部分 |
| 模型与模拟结果 | 计算、模拟、情景推演 | 带假设和适用范围，并标明有没有实验验证 | 方案01 E4；方案02“学术研究结果”中的模拟与模型部分；方案05 对计算研究的质量要求 |
| 专业判断 | 我们或他人依据多项证据作出的推断 | 写明依据、分歧和待验证之处 | 方案01 E5；方案02“专业判断与假设” |

六类是不同类型，不是从高到低的等级（R-03）。AI 生成的文字不属于任何一类，只能作为指向这些证据的草稿。

**层级（三层，已定，D-10）**　材料；组件或器件；系统。跨层级的数据不放进同一个可比组，也不画在同一张图上。

**可比性（四档，来自方案02 §5.3）**

| 档 | 含义 | 处理 |
|---|---|---|
| 直接可比 | 对象、测试方法、工况和边界足够接近 | 可以定量横向比较 |
| 条件化比较 | 有差异，但有合理的归一化或模型方法 | 说明条件与假设后比较 |
| 参考性资料 | 层级或系统边界明显不同 | 分开呈现，不排名 |
| 数据不足 | 缺关键参数、来源或有效性证据 | 写明缺什么，保留判断限制 |

**核验状态（六档，草案）**

| 状态 | 含义 | 由谁给出 | 能用在哪里 |
|---|---|---|---|
| 待核 | 刚录入，未检查 | — | 只在 dashboard 显示 |
| 机器已核 | 程序确认三件事：来源能解析到；原文片段能在来源文本里逐字找到；片段里的数值、单位与记录一致 | 程序，做的是确定性检查，不靠模型判断 | 只在 dashboard 显示 |
| 人工已核 | 人打开原文，确认数值、单位、条件、所指对象无误 | 成员或受托的人 | 可进对外报告的证据表 |
| 专业已复核 | 懂这个领域的人确认层级、条件是否齐全、可比档是否归对 | 成员或外部专家（Q-18） | 可进对比图表和判断 |
| 存疑 | 来源之间矛盾，或原文含糊 | 任何环节都可以标 | 对外使用时须写明分歧 |
| 作废 | 已被更正、来源撤稿或被新版本取代 | — | 保留记录，不再当作有效数据 |

### 2.6 证据记录的字段

| 字段组 | 字段 | 说明 |
|---|---|---|
| 身份 | 证据编号；所属题目 | 必填 |
| 对象 | 描述的实体；层级 | 必填。层级不填不能入库 |
| 内容 | 指标；数值或陈述；单位；原文给出的范围或误差 | 必填（范围或误差有则填） |
| 条件 | 指标字典规定的必须同时记录的条件，例如温度、压力、进料组成、电解液、电流密度、膜厚、测试方法 | 必填；原文没写的填“未报告”，不猜、不补。有“未报告”的记录不能归入“直接可比” |
| 类型 | 证据类型；是否有独立验证 | 必填 |
| 出处 | 来源编号；出处位置（页、表、图、段）；原文片段；取得方式（正文、表格、补充材料、图上读数、人工录入） | 必填。图上读数单独标记 |
| 时间与版本 | 来源发布日期；取得日期；最近核验日期；记录版本 | 必填 |
| 核验 | 核验状态；机器核对结果；核验人；核验时改了什么 | 必填 |
| 许可与可见范围 | 来源许可类别；可见范围（内部、可对外、某客户专属） | 必填 |
| 关联 | 重复数据指向原始记录；与之矛盾的记录；所在可比组 | 有则填 |
| 备注 | 适用范围与限制 | 有则填 |

十项元数据（R-01）的落点：原始来源、发布日期、版本、许可记在来源表；取得或核验时间、出处位置、单位、测试条件、核验状态记在证据记录；适用范围由对象、层级、条件和备注共同表达。

| F-11 | 提示可能的许可问题 | 按可见范围过滤输出 | 判断许可与保密 | 受版权限制的全文、付费库内容、对方保密资料不进仓库（R-23） |

| A 数据文件加生成的静态页面（建议） | 证据库是仓库里的结构化文件；脚本读这些文件生成一组网页；在本机打开，或由 Claude 发布成默认私有的网页 | 成本低；每次改动都有版本；图和下钻可以完全按本方案来；报告用同一份数据生成 | 页面只读；两人同时改数据不方便 | 不建数据库和服务，算样品的展示件 |
| B 现成的多维表格工具 | 证据表放进在线表格或多维表格，用它自带的视图和图表 | 不写代码；可以直接在表里改 | 点到原文片段、分层级作图、与报告同源这三点难做好；数据放在第三方工具里；版本记录弱 | 不涉及开发 |
| C 数据库加网页应用 | 建库，做可登录、可编辑的看板 | 交互完整，可多人用，离以后的产品最近 | 这就是软件开发；要维护；样品阶段的需求还没稳定 | 与 D-16 冲突，建议放到阶段 3 |

选 A 的话，用什么脚本和图表库属于实现，由 Yu 定（D-23、D-24）。

### 4.6 为以后给对方看留的余地

1. 每条记录有“可见范围”字段：内部、可对外、某客户专属。
2. 公共资产（行业包、公开来源的证据）和对方专属内容（题目卡里的背景、对方提供的资料、专属判断）从一开始就分开存放，不合并。
3. 内部备注和可对外的说明是两个字段。
4. 页面由数据加一份“视图配置”生成。给对方看的版本，就是同一份数据按可见范围过滤，再去掉 K7 这类内部页面。
5. 来源的许可类别决定能展示到什么程度：只给链接和摘要、可以给数据、可以再分发（方案01 IV.5 的三个层次）。
6. 现在不做账号、登录和对外的界面打磨。

## 5. 对外报告

### 5.1 定位

对外暂时只提供报告（D-26）。报告是证据库在某个问题上的一次呈现（R-24）：表和图由数据生成，正文依据判断记录来写，每个数都能对回证据编号。

### 5.2 结构

依据方案02 附录 C 的“跨模块研究成果的推荐结构”和方案01 附录 B 的研究报告模板整理。

| 节 | 内容 | 取自证据库的哪部分 |
|---|---|---|
| 1 问题与边界 | 要回答什么；对象、层级、范围；不包括什么 | 题目卡 |
| 2 结论摘要 | 每条结论和它成立的条件；目前不能下结论的部分 | 判断 |
| 3 方法与数据 | 检索范围和截至日期；纳入规则；来源与证据的数量；核验做到哪一步；已知缺口 | 检索记录；核验统计 |
| 4 证据与对标 | 分层级的对标表和图；可比档；证据类型 | 证据；可比组 |
| 5 关联 | 论文—团队—专利—企业—产品的对应 | 实体；关系 |
| 6 判断与依据 | 逐条写：结论、条件、依据、假设、分歧 | 判断 |
| 7 不确定与缺口 | 缺的数据、待核实的声明、存疑的记录 | 核验状态；“数据不足”一档 |
| 8 值得继续看的事项 | 以后可能改变判断的线索，不是行动建议 | 判断；变化记录 |
| 9 附录 | 证据表；来源清单（含出处位置）；指标口径；版本与变化说明；边界声明 | 证据；来源；指标字典；变化记录 |

### 5.3 学术方向与企业方向的写法差别

| 方面 | 学术方向 | 企业方向 |
|---|---|---|
| 侧重 | 科研使用场景：自己的结果处在什么位置、哪些比较成立；同时保留专利、初创、成熟企业、商业产品与应用（D-04） | 竞品与工程：同层级、相近工况下的公开性能，证据属于哪一类，有哪些替代路线 |
| 不写 | 对方熟悉的领域背景（D-05）；不预设对方想创业（D-04） | 我方的介绍（B03） |
| 层级 | 以材料和器件为主 | 材料、组件、系统都涉及，分开呈现 |
| 特别边界 | 计算与 AI 部分只做已有研究的情报（D-06） | 专利部分不是法律意见（D-10）；数字孪生属于技术情报，工程开发另行界定（方案02 §1.4） |

两种写法都不含我方的实施计划、时间线、预算和公司战略框架（D-07），都不替对方做选择（D-11）。

### 5.4 生成方式

1. 选定一个数据版本。
2. 程序由证据库生成表和图。
3. AI 依据判断记录起草正文，每句话带上它依据的证据编号。
4. 程序核对：证据编号存在；所引证据达到对外门槛；文中的数与记录一致；链接打得开。
5. 人审稿；懂行的人复核判断。
6. 导出完整文件。此前的方案都是 Word 文件，建议报告沿用 Word，可另存 PDF。
7. 记下报告编号对应的数据版本。

### 5.5 要求

| # | 要求 | 出处 |
|---|---|---|
| 1 | 每个数值、每张图表都对得上证据编号；附证据表和来源清单，来源写到页、表、图 | R-01、R-26 |
| 2 | 每条判断写清结论、成立条件、依据、假设、不能判断的部分 | 方案02 附录 C |
| 3 | 标明证据类型；企业声明不写成已验证的事实 | R-03、R-06 |
| 4 | 分层级呈现；不跨层级排名；不可比的分开列并说明原因 | R-04、R-05 |
| 5 | 写明截至日期、检索范围、纳入规则、核验做到哪一步、已知缺口 | 方案02 §11.3 |
| 6 | 不替对方选择，给条件和待确认的问题 | D-11 |
| 7 | 边界声明：不构成法律意见或 FTO 结论；不承诺实验与工程实施 | D-10 |
| 8 | 模块化，多用表格、矩阵、结构图；交付完整文件 | D-12 |

| 11 | 不出现证据库里没有依据的内容 | R-16 |

### 5.6 证据表给不给对方（见 J-02）

| 选项 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 报告附录含所引用的证据表（建议，样品阶段） | 报告里用到的每条证据，在附录里都有完整的一行 | 对方能自己核对，这正是我们要证明的东西；盲评里“来源定位”一项才评得了 | 把这部分数据交了出去 |
| B 报告加单独的表格文件 | 同 A，另给一份可筛选的表格 | 对方用起来更方便 | 同 A，且更容易被整体拿走 |
| C 只给正文和来源清单 | 证据表留在内部 | 资产留在手里 | 对方无法逐条核对，和通用 AI 的报告拉不开差别 |

## 6. 可视化、可追溯、信息准确

### 6.1 可视化

**规则**

1. 一张图只放一个层级。
2. 证据类型用形状表示，核验状态用实心与空心表示，可比档用分组与灰显表示。dashboard 和报告用同一套图例。
3. 颜色不单独承担含义，打印成黑白也看得懂。
4. 每张图写明对象数、筛选条件、截至日期和数据版本。
5. 不可比的不排名、不连线、不求平均。
6. 原文给了范围或误差就画出来；图上读数的点单独标记。
7. 不用三维图，不用跨层级的雷达图，不给企业算综合得分（方案02 §1.4）。
8. dashboard 里点得进去；报告里用编号对应到附录。
9. 不复制论文原图。

**图表清单**

| 图 | 回答什么 | 做法 | 用在 |
|---|---|---|---|
| 性能散点图 | 各对象在两项此消彼长的指标上处在什么位置 | 每个层级单独一张；一张图只放一个可比组，其余灰显 | K3；报告第 4 节 |
| 条件小多图 | 同一指标在不同条件下怎么分布 | 按条件分面，例如温度、压力、电流密度；缺条件的不画，列在图下 | K3；报告第 4 节 |
| 可比性矩阵 | 谁和谁能比，属于哪一档 | 行列是对象，格里是档别；“数据不足”写明缺什么 | K3；报告第 4 节 |
| 覆盖图 | 哪些对象的哪些指标有数据，核到哪一步 | 行是对象，列是指标，格里是最高的核验状态；空格就是缺口 | K1；报告第 7 节 |
| 关联图 | 论文、团队、专利、企业、产品怎么对应 | 分列排布，不画成一团网；实线有出处，虚线是推断 | K4；报告第 5 节 |
| 成熟度阶梯 | 一项技术有哪一级的证据 | 理论或模拟、材料实验、组件实验、中试、工业应用五级（方案02 §7.2），每级列出证据 | K5；报告第 6 节 |
| 时间线 | 何时发生了什么变化 | 论文、专利、产品、政策和我们自己的更正分行排列 | K6；报告“本期变化” |
| 核验漏斗与成本 | 核到哪一步，花了多少 | 只对内 | K7 |

**用在两个示例上**

- 企业示例：材料层画 CO₂ 渗透性对 CO₂/CH₄ 选择性的散点图，纯气和混合气的数据分开标。组件层和系统层不并进这张图，分别用带工况的表呈现；产品气纯度和甲烷回收率要连同级数、回流、压缩条件一起列，因为回收率高不能直接说明膜材料更好（方案02 §5.3 的“典型误区”）。
- 学术示例：膜层面画面电阻对活性物质渗透率；器件层面画各项效率随电流密度的变化。商业膜规格书上的数值用“企业声明”的形状标在同层级的图上；没披露测试条件的不进可比组，只列在参考性资料里。

### 6.2 可追溯

**正向：从结论追到原文**

```
报告里的一句话、图上的一个点
  → 判断记录：结论、成立条件、依据清单
  → 证据记录：数值、单位、条件、层级、类型、核验状态
  → 出处位置：第几页、哪张表、哪张图、哪一段，加原文片段
  → 来源记录：DOI、专利号或网址；版本；发布日期；取得日期；许可
  → 处理记录：谁或哪个流程在何时抽取、用的哪版模板；谁在何时核验、改了什么
```

**反向：从来源查到影响**　一个来源被更正、撤稿或换了新版本时：来源 → 受影响的证据 → 可比组 → 判断 → 已经发出的报告。

**做法**

| 事项 | 做法 |
|---|---|
| 编号 | 每类数据对象有固定前缀和不重复的编号：题目 TOP、来源 SRC、实体 ENT、证据 EV、关系 REL、可比组 CMP、判断 ASM、变化 CHG、报告 RPT。编号一经分配不复用 |
| 出处位置 | 精确到页、表、图、段，并保存原文片段。只写到“某篇论文”不算有出处 |
| 关系的出处 | 每条关系单独记来源；AI 推断而没有出处的关系标为“推断”，不当作已证实（R-02） |
| 网页来源 | 网页会变。入库时记取得日期、页面标题和关键片段；许可允许时留快照，否则留片段和存档链接 |
| 版本 | 数据文件放在仓库里，每次改动是一次提交，提交号就是数据版本。dashboard 和报告都印上所用的数据版本 |
| 流程版本 | 工作记录里写明所用的模型、模板和规则的版本。B 组的做法因此可以重复 |
| 一手优先 | 论文看出版方版本和补充材料，专利看官方登记，产品看厂家规格书，标准看发布机构。二手转述只作线索，不当出处（方案02 §11.2“真实性”） |

### 6.3 信息准确

**错误从哪里来，怎么挡**

| # | 错误 | 例子 | 控制手段 |
|---|---|---|---|
| 1 | 来源不存在或打不开 | AI 给了一个查无此文的链接 | 程序检查 DOI、专利号、链接能否解析 |
| 2 | 引用不支持所说的内容 | 标了引用，原文却没有这句话 | 证据必须带原文片段，程序逐字比对；人工核对 |
| 3 | 数值、单位抄错 | 小数点错位；mS/cm 记成 S/cm | 同一来源抽两遍并比对；单位与量纲检查；报告要用的数全部人工核对 |
| 4 | 条件挂错了对象 | 一段话里有两种膜，温度记到了另一种膜上 | 条件字段结构化；人工核对所指对象 |
| 5 | 层级混了 | 材料的选择性和组件的分离性能放在一起比 | 层级必填；图按层级分开 |
| 6 | 不可比的数据被比较了 | 高电导率是在更高温度或不同含水状态下测的（M004 的例子） | 指标字典规定必须同时记录的条件；懂行的人定可比档 |
| 7 | 重复数据 | 几篇论文和综述用的是同一组数据 | 追到原始出处；重复的指向原始记录 |
| 8 | 实体认错 | 同名企业；同一专利族的多件申请被数成多项 | 按专利族归并；关键合并由人确认 |
| 9 | 过时 | 专利状态已变；产品已停产；标准已被替代 | 每条记录有最近核验日期；报告写明截至日期 |
| 10 | 声明当成了事实 | 厂家宣称的寿命写成已验证 | 证据类型必填；展示规则 |
| 11 | 漏了重要的 | 关键论文或竞品没查到 | 检索方案覆盖多个来源；顺着引文追查；请内行列“必须有”的清单来检验查全 |
| 12 | 判断越界 | 给了唯一推荐；下了法律结论；跨层级排名 | 判断模板要求写条件和未知；复核清单 |
| 13 | 成文时混进没依据的内容 | AI 起草时顺手补了一句“业内普遍认为” | 正文只依据判断记录来写；发出前程序核对 |

第 1、2、3、4 类错误的发生率，现有研究里有数字，见第 7 章。

**五道关口**

| 关口 | 查什么 | 由谁 | 不过怎么办 |
|---|---|---|---|
| 1 来源入库 | 能解析到原始出处；类型、发布日期、许可、取得方式已登记 | 程序加人 | 不入库，或只作线索 |
| 2 证据入库 | 原文片段逐字可查；数值、单位与片段一致；条件齐全或标了“未报告”；层级已填 | 程序 | 退回重抽，或交给人 |
| 3 进入对比之前 | 人工核对数值、单位、条件、对象；去重；定层级和可比档 | 人，含专业复核 | 留在库里，不进对比 |
| 4 判断定稿之前 | 每条判断有依据清单、成立条件、未知；没有越界 | 人，专业复核 | 改写或撤下 |
| 5 报告发出之前 | 文中每个数与记录一致；所引证据都达到对外门槛；链接打得开；脱敏、版权、边界声明都查过 | 程序加人 | 不发 |

**对外门槛（建议，见 J-06）**　报告证据表里的记录至少是“人工已核”；用于对比图表和判断的记录须“专业已复核”；“存疑”的记录要用就写明分歧；“待核”和“机器已核”的记录不出现在对外报告里。库里没被报告用到的记录，按抽样核对。

**怎么度量**　沿用《路线图》§4 的“内容质量”一组，具体记：来源完整率；机器核对通过率；人工核对的改动率（按上表的错误类型分）；条件缺失率；重复数据的比例；专家修订的条数；评审人或专家指出的遗漏；从发现错误到更正的用时。目前都没有实测值，门槛数值等第一份样品做完再定（Q-12）。

## 7. 大模型目前能做到的程度与人机分工

以下是 2026-11-10 查到的情况。被测的多是评测当时的模型，现在的模型可能更好；这些数字只用来看量级和薄弱环节在哪里。

### 7.1 分任务的现状

| 任务 | 现在能做到什么 | 短板 | 出处与性质 |
|---|---|---|---|
| 多步检索并写成带引用的报告 | 通用工具都能在几十分钟内完成：联网检索、读上传的文件、连接外部数据，输出带引用的长报告，可以先给研究计划 | 事实与引用是弱项。DeepTRACE 审计发现各系统的引用准确率在 40%–80% 之间，且有大量陈述得不到所列来源的支持。DRACO 基准（100 题）里，各系统的事实准确得分约 40%–68%，引用质量约 42%–65%，普遍是呈现质量最好、事实准确和引用质量最差。OpenAI 自己也写明：会编造事实、难以区分权威信息与传闻、对把握程度表达不准 | B-01、B-02、B-03 为厂商说法；B-05、B-06 为学术评测，其中 B-06 的作者多来自 Perplexity，被测的是 2026 年初的模型 |

### 7.2 这些情况对设计意味着什么

1. 报告写得像样已经不是差别，差别只能来自内容经不经得起核对。所以整套设计以证据记录为中心，不以报告为中心。
2. 引用要落到原文片段，由程序逐字比对；链接由程序检查能否打开。链接这一类，现有研究显示自动检查能把打不开的比例压到 1% 以下〔B-07〕。引用这一类，片段比对只能保证原文确有这句话、数值一致；条件和所指对象对不对，仍然要人看。
3. 数值抽两遍，结果不一致的交给人；报告要用的数值全部人工核对。
4. 图上读数单独标记，优先去找源数据表或补充材料；要对外使用，须由人复读并写明读数误差（J-07）。
5. 跨文献对齐条件是目前最不可靠的一步，而它正是“条件化对标”的核心。所以条件字段要结构化，缺的就标“未报告”，可比档由懂行的人来定。人工应该集中投在这里，我们假设的增量也在这里。
6. 这些数字会变，核验深度因此做成可调的：每次人工核验都记下改了什么，等自己的数据显示某类错误已经很少，再把那一类从全部核对改为抽检。
7. 模型进步同样会降低对方自己做的成本（交接《AI 替代风险》§3）。三组对照不是做一次就完，换了模型要重测。

### 7.3 人机分工

各模块的分工见 3.2。归纳起来：

| 由谁 | 做什么 | 理由 |
|---|---|---|
| AI | 检索、初筛、抽取、候选归并与关联、预归类、起草 | 量大、重复，现在已经做得快，错了有后面的检查兜着 |
| 程序 | 链接与标识符检查、原文片段比对、单位与量纲检查、两遍结果比对、门槛检查、反查影响范围、生成图表 | 能写成规则的检查不交给模型，同样的输入总得到同样的结果 |

### 8.2 从查证里看到的四个动向

1. 各家都在自己的数据上加“深度研究”智能体，并强调引用或可追溯：AlphaSense、Scopus AI、GlobalData、Wood Mackenzie、CB Insights 都是这样〔B-19、B-21、B-25、B-28、B-26〕。“带引用”已经不是卖点。
2. 数据厂商正通过 MCP 把数据接进客户自己的 AI：CB Insights、Wood Mackenzie、企查查、智慧芽都提供了接口，ChatGPT 和 Gemini 也能接入〔B-27、B-28、B-31、B-18、B-01、B-02〕。对方的 A 组会越来越强；我们也可以用同样的方式取数。
3. 智慧芽提出“从交付工具到交付成果”并派人驻场〔B-18〕。大厂也在往服务走。
4. 本轮读到的页面里，没有哪家公开讲“按测试条件判断数据能不能比”这件事。Elicit 做到了每个值附引文，但它面向的是系统综述。这只说明公开材料里没看到，不能断定它们做不到。

**不算优势的**（D-09；方案01 VI.3）　自动生成报告；知识图谱；Agent；带引用；数据条数。这些市场上都有成熟的供给。

**对手明显强过我们的**　数据规模和许可；专利与企业数据的完整程度；品牌和销售；通过 MCP、Copilot 进入客户日常工作的渠道；一手访谈。

**我们可能有的条件**（未验证）　主题窄，可以核得很细；成员的领域背景和与两位潜在对象的接触（M006 里此前助手的说法）；团队小，借 AI 可以把成本压低。

### 8.5 定位建议（见 J-09）

不和数据平台比规模，把它们当上游、工具或对照。自己做一件事：在窄主题上，交出经得起逐条核对的条件化对标和关联，并用三组对照来证明。对外不把 AI 报告、知识图谱、Agent 说成独有的技术（D-09），比较时落到具体任务，不作“全面领先”一类的表述（交接《竞品与资料入口》§1）。

### 9.3 使用 AI 的注意事项

1. AI 生成的文字不是证据（R-03）。
2. 检索到的网页是不可信的输入，里面可能嵌着写给 AI 的指令。检索到的内容一律当数据，不当指令。
3. 换模型后，同一套流程的结果会变。工作记录里写明所用的模型和模板版本，换模型后抽样复测。
4. 把对方的资料交给模型处理之前，先确认服务条款和对方的授权：是否允许、数据存在哪里、是否会被用于训练。这一点还没查（Q-16）。
5. A、B 两组由同一个 AI 执行，独立性有限，结论要谨慎解读（《路线图》阶段 1）。
6. 如果 dashboard 由 Claude 发布成账号内的网页，两位成员看到的是同一份；账号使用方式本身的问题仍在 Q-24。

## 10. 分期

阶段沿用《路线图》的划分（D-16）。下表只说每个阶段做到哪一步，不排日期（清单 I-03 未定）。

**样品阶段的最小集合**　题目卡和指标字典；来源表；证据表；可比组；判断记录；工作记录；机器核对的三项检查（链接与标识符、原文片段、单位）；dashboard 的 K1、K2、K3、K5；一份报告模板。

**现在明确不做的**　数据库和后端服务；账号与权限；自动采集流水线；可编辑的看板；API；第二个行业包。
